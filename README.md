# DrawY

AI 创作可以探索和修改的图。界面按 Claude 官网与桌面端的气质设计：象牙底、墨色字、赤陶色点缀，标题用衬线字，少用文字说明、多用图标，卡片落在燕麦色和柔和色块上。界面支持中文与英文，在登录页或账户菜单里切换，选择保存在浏览器里。左侧栏是首页（新作品从这里开始）、素材库和全部作品（可重命名，删除后几秒内可撤销），账户菜单里是设置、运行记录和语言。绘图页只有四块：左侧栏、顶部的作品标题与场景路径、中间的画布，以及右侧可折叠的工具栏（撤销、重做、手动编辑、版本、创作过程、下载图片）。一步是一次请求连同作者为它保存的所有稿，或一次手动编辑；撤销（⌘Z）按步回退，撤销后作品没再变动时可以重做（⇧⌘Z），版本面板按步列出、点开可在画布上预览再恢复。下载图片由截图服务按场景全幅以两倍清晰度渲染。子场景有自己的地址，浏览器后退回到上一层。画布上点选模块，再拖动即可移动，拖空白处平移。

作品画好后不懂代码也能自己改。点工具栏的铅笔进入编辑（选中模块后输入框旁的“手动修改”、或在画面上双击文字也能进入），右侧换成编辑面板：点选即选中，可以直接拖动，Shift 多选，按住右下角圆点缩放；双击文字就地改字，双击图片从素材库换一张或上传新图；面板把选中模块能调的东西做成普通控件（文字框、作品色板加任意色、滑块、开关、选项），还有复制、置顶、置底、删除，以及它的连线（可展开调整或删掉）；没选中时可以添加文字或图片，改作品的线条色、强调色和字体。方向键微调位置，⌘D 复制，Delete 删除，⌘]/⌘[ 调整上下层。每次修改立即保存为一个新版本，可撤销重做。由画法计算出来、改不到的文字或图片，会把修改要求写进输入框交给 AI。编辑时画上的按钮和入口不响应，以免误触；AI 创作期间不能编辑。下次请 AI 修改时，作者会被告知用户自己改过哪些地方，并保留这些修改。同一浏览器的多个标签页共用一条事件连接。画布下方的输入框同时显示作者当前的动作、正在挑选的图片、提问（编号列表，点选即答，每题最后一行可以自己写答案）和最后的回复；输入框的回形针可以上传图片或从素材库选择。素材库按所在空间分页显示，不滚动；公共素材、我的素材分栏显示，能看所有素材的角色还多一栏“其他用户”，素材详情写明归属。设置页左侧是偏好，以及按角色权限出现的绘制模型、图片模型、账号、角色几栏。输入框右下角是模型选择（仿 Claude）：列出管理员接入的绘制模型和各自的说明，选择会记住。首页输入框可先选画风，图片可拖到页面任意处作为参考。画布负责平移、缩放、选择、移动与调整模块大小，作品保存内容和画法。

作品包含七部分：`brief` 是动笔前定下的创作简报（主题、意图、受众、立意、严谨或个性的语域、风格、美术方向和出场角色），主题与意图的依据必须逐字引用用户说过的话，语域没有说到时由作者按题材选定；立意是作者自己选定的视觉想法：画面先让人看到什么、各部分怎样排布、这种排布说明了什么，它不需要引用，后续修改沿用它，直到请求要的东西它装不下；`drawings` 保存 AI 编写的可复用绘制代码；`scenes` 用模块实例、分组和锚点连接组成场景；`interactions` 保存场景事件与动画；`details` 保存独立打开的说明；`materials` 是作品取用的素材快照；`style` 保存共享样式，选定风格时由风格素材填入。实例包含自己的数据、位置、尺寸和导航目标。相同画法可用于多个实例，画法代码与实例数据分别修改。画法用 `params` 声明哪些实例数据可以手动修改，每项有给人看的名字和类型（文字、数字、开关、颜色、图片、选项），编辑面板据此生成控件；库里的画法参数用同一套类型。

画法接收 `api`，返回 DOM/SVG 元素。`api.svg/html` 创建局部内容，`api.mermaid/plantuml` 渲染 UML 一类只有它们能画的记法（层级、分层、矩阵、对比、流程这类结构图用库里的结构画法，更好看，也跟随作品风格），`api.material(id)` 按图片的可见内容放入图像素材（默认立在框的底边，不透明的整幅画边缘羽化入纸），`api.materials` 提供图片的尺寸与语义锚点，`api.draw(id, data)` 调用画法素材（模块和连线也可以直接以库里画法的 ID 作为 `drawingId`，数据即其参数），`api.effect(id)` 套用质感素材，`api.emit` 触发场景事件。连线的画法还会拿到 `api.fromSide/toSide`，即两端锚点各在所属模块的哪条边上，直角走线据此垂直离开和进入模块。画法代码里字面调用、作为 `drawingId` 或在模块数据里出现的素材 ID 会在保存时自动取入作品，不再被任何代码或数据提到的素材随之移出；库里的画法和质感每次保存都重新取当前版本，所以作者照着素材目录写的参数总能被作品里的代码读懂，没再保存过的作品仍按当时的版本显示。场景交互通过 `api.on/set/move/openScene/openDetail` 操作实例和导航；异步工作使用 async/await，动画与外部监听通过 `api.animate/cleanup` 管理生命周期。交互状态随场景离开而释放，持久数据通过 `write_work` 原子保存为新版本。画法由 AI 定义，产品没有预设图种注册表。

```sh
docker compose up -d --build
```

访问 http://localhost:8088。第一个注册的账号是管理员，之后注册的是普通用户。管理员在设置中接入绘制模型和生图模型，全站共用；支持 OpenAI API Key 与 ChatGPT OAuth。可以接入多个绘制模型，各有显示名称、说明、速度（API Key 有 Flex、Default、Fast，ChatGPT OAuth 有 Default、Fast、Ultrafast）与思考强度，并指定一个默认；普通用户看不到凭证和参数，只在输入框里选择用哪个模型。

账号按角色授权。内置两种角色：管理员拥有全部权限且不能修改；普通用户是新账号的默认角色，权限可以调整。管理员还可以新建角色，在设置的“角色”栏逐项开关权限，在“账号”栏给每个账号分配角色。权限有四项：管理模型、查看和使用所有素材（含其他用户的私人素材）、管理素材（把用户的图片设为公共或收回为私人）、管理账号与角色。系统始终至少保留一位管理员。从旧版本升级时，最早注册的账号成为管理员，它原来自己配置的模型连接成为全站的第一个模型；其他账号只保留长期偏好。数据位于 `./data`；`DRAWY_PORT` 设置端口；可在本地 `.env` 中设置 `DRAWY_OUTBOUND_PROXY` 和 `DRAWY_NODE_OPTIONS`。

```sh
pnpm install
pnpm typecheck
pnpm test
```

`contracts` 定义作品协议；`workspace` 管理原子修改与版本；`editing` 把画布上的手动操作（改数据、改字、换图、删除、复制、调层级、添加）变成一次作品修改，文字或图片 ID 在模块数据里就改数据，在画法代码里只出现一次就改代码（画法被别的模块共用时先为这个模块复制一份），并能列出两个版本之间的差别；`runtime` 执行画法和场景交互；`canvas` 管理视角与编辑手势，并把创作过程画在纸上：作者工作时有一支铅笔，`write_work` 的构图一到就用石墨线起稿并写上名字，某个画法的代码到齐后给用到它的草稿排上阴影；某次保存失败时草稿保留到作者下一次写入；生成中的图片在它将出现的位置排着铅笔线，到达时像照片一样显影；保存的新版本在后台绘好后原地替换，新增或改动的模块按作者列出的顺序落笔，线条沿路径勾出、填色随后铺上、图片显影、文字逐字写出，铅笔跟着笔尖走，移动的模块滑到新位置，镜头随构图平滑过渡；`agent` 编排创作工具，把思考摘要、进度说明和每次工具调用及其结果（素材候选、生成图片、保存内容、画布截图）按发生顺序记录为运行步骤，并在工具参数流式到达时解析出已完成的部分（作品修改先写场景构图、后写画法，模块先写名字和位置），`view_canvas` 的查看区域显示为取景框；空白画布上会钉出作者找到的素材和正在显影的生成图片，画布下方的输入框顶部展示当前动作，创作过程面板按步骤展示每次运行；`observation` 调用截图服务，将整图、局部、坐标标注和交互状态作为图片送回作者的同一段对话；`models` 调用创作模型，同一用户的请求共用一个缓存键（ChatGPT 账号通道同时放进 `session_id` 头，它按这个头把请求送到持有缓存前缀的机器），上下文压缩另用 `<用户>:compact`；决定作品的轮次（回应请求或回答的第一轮，在这里定简报、立意或决定要不要问；每次看图后的一轮，在这里评判）在对话里插入 `configuration_update` 把推理强度临时升到 max，之后执行的轮次回到设置的强度，请求本身的强度不变，缓存前缀照样命中（GPT-6 模型支持这种输入项）；系统提示词里的素材目录只写随代码变化的内容并按 id 排序，不随图片数量和使用次数变化，所以每个请求的前缀都相同，新作品的第一轮和作品续画都能命中缓存；`images` 按作品风格在后台显影图片：除了风格句，还把作品里已有的同风格图片和风格样张（同类角色优先，最多两张）作为风格参考图一起交给生图模型，提示词说明哪些图是要照着画的内容、哪些只取画风，这样后生成的图和先放进作品的图看起来是一套；先在素材库预留 ID，作者立即可以使用，`view_canvas` 等它们显影，每张显影后都给作者看一眼；`materials` 是主程序访问素材库的一层；`trace` 用独立的 `trace.sqlite` 记录每次运行：执行开始时的完整上下文、系统提示词和工具；每个模型轮次的请求参数、新增输入、输出（思考摘要、回复、工具调用）、用量与缓存命中、首字延迟和响应 ID；工具参数、结果与返回给模型的图片；素材检索的每个命中及其分数；生图的提示词、参考图与风格参考图、每次请求尝试和结果；截图与交给模型的几何。模型看到的每张图按内容哈希存成文件，记录里引用其地址。记录按异步上下文嵌套，任何模块无需传参即可记录；运行记录页按时间轴查看，每一轮可还原出模型收到的完整输入，按对话呈现，也可看原始 JSON；`identity/storage` 按用户隔离账号、作品、版本、任务、截图和偏好，并保存角色、权限和全站共用的模型配置。

素材是让图画得更快更好的现成成分，由独立的 `@drawy/materials` 包和服务管理，有自己的数据库、文件、检索与 HTTP 接口，可以单独运行。素材分四种：`picture` 图像（物件、人物、场景、图标、纹理，记录画面内容、画风、可见内容框、语义锚点和主色）、`drawing` 画法代码（箭头（可直角走线）、引线标注、循环、函数曲线、时间轴、滑块、分段选择，以及结构图：流程与架构的节点、层级树、分层结构、四象限、对比表、金字塔与漏斗、韦恩图、思维导图、步骤进度、泳道、鱼骨图、时序图、同心圆；图表：柱状图、环形图、仪表盘、关键数字、雷达图、甘特图；对话气泡和清单；还有地图，底图是真实的海岸线、湖泊、带名称的河流、地势晕渲和可选的国界与各国一级行政区（省、州），世界尺度用圆润的 Natural Earth 投影，国家尺度只标主题国家的省名、邻国只标国名，放大到两百公里左右时换成 OpenStreetMap 的真实水系和主干道，再放大到城市时出现街道、公园和铁路并标出主干道名，地点、路线和区域按经纬度放上去，路线可分段着色、调粗细和标方向，真实河流可以按名称突出（整条，或两个地点之间的一段），标签自动避开彼此和路线。这些都是可调参数的绘制与交互函数，颜色和字体取自作品风格，可套风格的质感，每个都带一份示例数据，素材库据此实时画出预览，作者的目录里也附上它）、`effect` 质感（铅笔颗粒、手绘抖边、水彩晕边、排线等 SVG 定义）、`style` 风格（语域、色板与字体 token、手绘规则、配套质感、生图风格句和样张；绘画类风格的首张样张是同一幅海边灯塔小景，并排就能比出画风）。每个素材都有中英名称、别名、分类与说明；检索按字段加权，中文按字对切分并以覆盖率区分 exact/close/related，所选风格优先。地图的地理数据来自 Natural Earth，随策展素材放在 `materials/seed/geo`（总览地形、国界、一级行政区三层，近景另有按 15° 分块的细海岸线，另有三级分块的地势晕渲图；一张图通常只读几百 KB），按图层由素材服务提供，画法用到时才读取；政治图层统一采用一个视角（目前是中国视角），争议边界按该视角的分类画成虚线，不承认的线不画。地区和城市尺度的底图由素材服务按需从 OpenStreetMap 矢量瓦片（默认 OpenFreeMap，可用 `DRAWY_TILES_URL` 更换）取来并缓存在 `data/materials/streets`，所以素材服务需要能访问外网；取不到时地图退回 Natural Earth 底图并在图上注明。素材严格分为公共和私人两类：策展素材和被管理素材的人设为公共的图片是公共素材，所有人可见可用；用户上传或让 AI 生成的图片（带着作者给的名称入库）都是这个用户的私人素材，只有本人和有“查看和使用所有素材”权限的角色能看见、使用。风格样张只取公共图片。作者检索素材时只在公共素材和本人的私人素材里找。策展素材在 `materials/seed`。

提示词参考 [GPT-6 Astra 官方指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)和 [Opus 5.5 官方指南](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)，保留明确的作品协议、简短工具约定和实际看图修改。

作者先理解再动笔，再自己决定怎么画：用户的话决定画什么、给谁看，画面怎么构成由作者负责。它先在 `set_brief` 里写下两三种画法（`ideas`），每种标明种类且互不相同：惯例（这类题材通常画成的样子）、剖面（真实的样子，整体、剖开或切开）、旅程（在空间里走一遍）、变化（同一处随时间）、比例（真实大小的对照）、机理（背后的力或原因在起作用）、类比（结构相同的日常情境）、情景（有人物的一刻）；种类不同，想法才是真正的备选，而不是第一个念头的变体。再从中选出观众最快看懂或最能感受到的一种展开成立意；这几种想法只留在这次运行的步骤里，创作过程面板把它们列在立意下面。字段顺序让想法先于立意生成，所以发散真的发生在落笔之前，而不依赖模型的隐式思考；惯例的排法（一排图片加箭头、一堆方框、人物配符号、与请求同名的库画法）只是其中一种，只在题材本来就是那种结构、或用户点名时才选；位置、方向、大小、远近和分组本身要说出真实的关系，发明不能以准确为代价。每次看图按顺序评判：先看所说的是否都对，再看立意是否一眼读得出，最后看工艺，然后找出最弱的地方，观众会注意到就改，立意没出来时重新构图而不是改标注；看完用一句话告诉用户画面现在对立意说出了什么、接下来改什么。请求说不清主题的含义或要表现的方面时（例如只说“苹果”），用 `ask_user` 一次问清（只缺语域时不问，作者自选并在进度里说明），选项可附风格样张，用户可以点选、在输入框里补充（随所选选项一起发出）、交给作者决定，或者不画了；`set_brief` 定下后，空白纸上先钉出一张便签写着作者理解的主题、意图、立意、受众和画风，创作过程面板里也记下这条立意；`set_brief` 定下简报，返回风格的 token、手绘规则、质感和出场角色的库内素材（附缩略图）；库里没有或风格不符的东西用 `generate_images` 一次性批量生成，同批图片可按 key 互相引用以保持同一角色；之后通过 `write_work → view_canvas → write_work` 逐步绘制与查看。`view_canvas` 可指定场景、画布坐标区域、对象标注和连续点击操作，并报告每个模块用了哪些素材、图片可见内容在场景中的实际位置；截图前附上简报的意图和立意供对照，全图还报告整幅图占开场视图的比例（`figure.viewFilled`），一长条横排只占三成左右，作者据此把构图收进视图；截图服务不可用时重试后结束本次运行；与模型的连接中断、限流或服务端出错时整轮重试，先撤回这一轮已显示的半截内容；完成前必须看过最新版本的所有非空场景，且截图没有运行错误。`capture` 服务只负责浏览器截图，作品没有独立检查模型或评分关卡。
