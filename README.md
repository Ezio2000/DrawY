# DrawY

AI 创作可以探索和修改的图。界面按 Claude 官网与桌面端的气质设计：象牙底、墨色字、赤陶色点缀，标题用衬线字，少用文字说明、多用图标，卡片落在燕麦色和柔和色块上。界面支持中文与英文，在登录页或账户菜单里切换，选择保存在浏览器里。左侧栏是首页（新作品从这里开始）、素材库和最近作品，点“最近”进入作品画廊（以作者最后看到的整图为封面，可重命名，删除后几秒内可撤销），账户菜单里是设置、运行记录和语言。绘图页只有四块：左侧栏、顶部的作品标题与场景路径、中间的画布，以及右侧可折叠的工具栏（撤销上一稿、版本、从素材库添加、创作过程）。画布下方的输入框同时显示作者当前的动作、正在挑选的图片、提问和最后的回复。首页输入框可先选画风，图片可拖到页面任意处作为参考。画布负责平移、缩放、选择、移动与调整模块大小，作品保存内容和画法。

作品包含七部分：`brief` 是动笔前定下的创作简报（主题、意图、受众、严谨或个性的语域、风格、美术方向和出场角色），每项依据都必须逐字引用用户说过的话；`drawings` 保存 AI 编写的可复用绘制代码；`scenes` 用模块实例、分组和锚点连接组成场景；`interactions` 保存场景事件与动画；`details` 保存独立打开的说明；`materials` 是作品取用的素材快照；`style` 保存共享样式，选定风格时由风格素材填入。实例包含自己的数据、位置、尺寸和导航目标。相同画法可用于多个实例，画法代码与实例数据分别修改。

画法接收 `api`，返回 DOM/SVG 元素。`api.svg/html` 创建局部内容，`api.mermaid/plantuml` 渲染结构化图，`api.material(id)` 按图片的可见内容放入图像素材（默认立在框的底边，不透明的整幅画边缘羽化入纸），`api.materials` 提供图片的尺寸与语义锚点，`api.draw(id, data)` 调用画法素材（模块和连线也可以直接以库里画法的 ID 作为 `drawingId`，数据即其参数），`api.effect(id)` 套用质感素材，`api.emit` 触发场景事件。画法代码里字面调用、作为 `drawingId` 或在模块数据里出现的素材 ID 会在保存时自动取入作品，不再被任何代码或数据提到的素材随之移出。场景交互通过 `api.on/set/move/openScene/openDetail` 操作实例和导航；异步工作使用 async/await，动画与外部监听通过 `api.animate/cleanup` 管理生命周期。交互状态随场景离开而释放，持久数据通过 `write_work` 原子保存为新版本。画法由 AI 定义，产品没有预设图种注册表。

```sh
docker compose up -d --build
```

访问 http://localhost:8088。注册账号后在设置中配置创作和生图模型；支持 OpenAI API Key 与 ChatGPT OAuth。创作模型有 Fast 与思考强度设置，生图模型单独选择。数据位于 `./data`；`DRAWY_PORT` 设置端口；可在本地 `.env` 中设置 `DRAWY_OUTBOUND_PROXY` 和 `DRAWY_NODE_OPTIONS`。

```sh
pnpm install
pnpm typecheck
pnpm test
```

`contracts` 定义作品协议；`workspace` 管理原子修改与版本；`runtime` 执行画法和场景交互；`canvas` 管理视角与编辑手势，并把创作过程画在纸上：作者工作时有一支铅笔，`write_work` 的构图一到就用石墨线起稿并写上名字，某个画法的代码到齐后给用到它的草稿排上阴影；某次保存失败时草稿保留到作者下一次写入；生成中的图片在它将出现的位置排着铅笔线，到达时像照片一样显影；保存的新版本在后台绘好后原地替换，新增或改动的模块按作者列出的顺序落笔，线条沿路径勾出、填色随后铺上、图片显影、文字逐字写出，铅笔跟着笔尖走，移动的模块滑到新位置，镜头随构图平滑过渡；`agent` 编排创作工具，把思考摘要、进度说明和每次工具调用及其结果（素材候选、生成图片、保存内容、画布截图）按发生顺序记录为运行步骤，并在工具参数流式到达时解析出已完成的部分（作品修改先写场景构图、后写画法，模块先写名字和位置），`view_canvas` 的查看区域显示为取景框；空白画布上会钉出作者找到的素材和正在显影的生成图片，画布下方的输入框顶部展示当前动作，创作过程面板按步骤展示每次运行；`observation` 调用截图服务，将整图、局部、坐标标注和交互状态作为图片送回作者的同一段对话；`models` 调用创作模型，同一用户的请求共用一个缓存键（ChatGPT 账号通道同时放进 `session_id` 头，它按这个头把请求送到持有缓存前缀的机器），上下文压缩另用 `<用户>:compact`；系统提示词里的素材目录只写随代码变化的内容并按 id 排序，不随图片数量和使用次数变化，所以每个请求的前缀都相同，新作品的第一轮和作品续画都能命中缓存；`images` 按作品风格在后台显影图片：先在素材库预留 ID，作者立即可以使用，`view_canvas` 等它们显影，每张显影后都给作者看一眼；`materials` 是主程序访问素材库的一层；`trace` 用独立的 `trace.sqlite` 记录每次运行：执行开始时的完整上下文、系统提示词和工具；每个模型轮次的请求参数、新增输入、输出（思考摘要、回复、工具调用）、用量与缓存命中、首字延迟和响应 ID；工具参数、结果与返回给模型的图片；素材检索的每个命中及其分数；生图的提示词、参考图、每次请求尝试和结果；截图与交给模型的几何。模型看到的每张图按内容哈希存成文件，记录里引用其地址。记录按异步上下文嵌套，任何模块无需传参即可记录；运行记录页按时间轴查看，每一轮可还原出模型收到的完整输入，按对话呈现，也可看原始 JSON；`identity/storage` 按用户隔离账号、作品、版本、任务、截图和设置。

素材是让图画得更快更好的现成成分，由独立的 `@drawy/materials` 包和服务管理，有自己的数据库、文件、检索与 HTTP 接口，可以单独运行。素材分四种：`picture` 图像（物件、人物、场景、图标、纹理，记录画面内容、画风、可见内容框、语义锚点和主色）、`drawing` 画法代码（箭头、引线标注、循环、函数曲线、时间轴、滑块、分段选择等可调参数的绘制与交互函数，每个都带一份示例数据，素材库据此实时画出预览，作者的目录里也附上它）、`effect` 质感（铅笔颗粒、手绘抖边、水彩晕边、排线等 SVG 定义）、`style` 风格（语域、色板与字体 token、手绘规则、配套质感、生图风格句和样张）。每个素材都有中英名称、别名、分类与说明；检索按字段加权，中文按字对切分并以覆盖率区分 exact/close/related，所选风格优先。生成的图片带着作者给的名称入库，没有用私人参考图的公开给所有用户检索复用；上传的图片归上传者。策展素材在 `materials/seed`。

提示词参考 [GPT-6 Astra 官方指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)和 [Opus 5.5 官方指南](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)，保留明确的作品协议、简短工具约定和实际看图修改。

主程序沿用 SeeY 的 MIT 授权；`materials/seed/files` 中的插画与双色图标和 `modules/ui/brand` 为原 SeeY Art 私有素材，`line-*` 图标来自 Lucide（ISC），见 `materials/LICENSE`。

作者先理解再动笔：请求说不清主题的含义、要表现的方面或语域时（例如只说“苹果”），用 `ask_user` 一次问清，选项可附风格样张，用户可以点选、在输入框里补充（随所选选项一起发出）、交给作者决定，或者不画了；`set_brief` 定下后，空白纸上先钉出一张便签写着作者理解的主题、意图、受众和画风；`set_brief` 定下简报，返回风格的 token、手绘规则、质感和出场角色的库内素材（附缩略图）；库里没有或风格不符的东西用 `generate_images` 一次性批量生成，同批图片可按 key 互相引用以保持同一角色；之后通过 `write_work → view_canvas → write_work` 逐步绘制与查看。`view_canvas` 可指定场景、画布坐标区域、对象标注和连续点击操作，并报告每个模块用了哪些素材、图片可见内容在场景中的实际位置；截图服务不可用时重试后结束本次运行；与模型的连接中断、限流或服务端出错时整轮重试，先撤回这一轮已显示的半截内容；完成前必须看过最新版本的所有非空场景，且截图没有运行错误。`capture` 服务只负责浏览器截图，作品没有独立检查模型或评分关卡。
