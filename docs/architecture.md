# DrawY 开发文档

## 一次运行如何流动

1. 用户在某个场景发出请求。`apps/server/app.ts` 收到 `POST /api/works/:id/runs`，调用 `modules/agent` 的 `Agent.start`。
2. 同一作品的对话上下文会延续：新一次运行沿用上一次运行保存的 `input`，再追加用户消息和作品当前的状态。保存的对话格式不是当前的 `CONTEXT_FORMAT` 时不续用，换成用户说过的话加整份作品。`Context.known` 记下对话已持有的版本（作者保存、`read_work`、`set_brief` 或压缩后整份给出的那一版），`catchUp` 据此只发变化：没变时只说一句"作品和上次一样"；用户在两次运行之间自己改过作品（手动编辑、撤销或恢复）时，列出作者上次保存之后哪些模块被改、移动、添加或删除，以及哪些场景（含脚本）、画法和详情被增删改（`editing.changesBetween`），并附上这些记录的当前样子（`changedRecords`，模块用作者写的短写法），提示词要求作者保留这些修改；对话里没有这件作品、中间有作者不知道的作者保存，或变化超过整份作品一半时，仍整份发送。用户的长期偏好以 `User preferences: …` 消息放在对话里（`Context.preferences`），变了才再发一次，系统提示词因此对所有用户相同。
3. 作者按 `modules/agent/tools.ts` 里定义的工具工作：
   - `ask_user` 暂停运行，状态变为 `waiting`，用户回答后由 `resume` 继续。`start` 在首次异步操作前读取完整 `Settings`，存入服务端持久化的 `Context.settings`；恢复、绘制循环、压缩、搜索、生图与简报偏好校验都使用此快照，不重读账号设置。`run.services` 和 `run.prices` 从此快照生成，跨作品选择或管理员改价不会影响已有运行；新运行单独读取最新设置，只继承旧运行的对话，不继承配置。完整快照含连接凭证，只存在服务端 context，不放入公开 Run 或 trace。
   - `set_brief` 定下简报。
   - `find_materials` 检索素材库（所有类型平级，`types` 过滤），每个主题只回几条短描述和匹配程度，图片最多看 6 张；`cards: true` 时顺带给出每个主题最佳的画法、风格或效果卡片（作者已确定要用某种形式时，找和读在同一轮完成，避免多一轮）。
   - `read_materials` 按需读取素材卡片：画法的参数、默认尺寸和示例，风格的 token 与指南，图片的锚点，效果的用法；作品已持有的素材按它持有的版本读。
   - `draw_guide` 按需读取指南（渐进式披露，见“提示词的三层”）。
   - `generate_images` 在后台生成图片（`modules/images`）。这些图片先全部在素材库里预留 ID，作者马上就能引用；`develop` 先检查（批内引用不能成环、批外引用必须存在，否则整批不开画），引用同批图片的那张等被引用的显影后才开始（被引用的失败时它也不画），其余并行。每张图除了作者给的内容参考图，还会带上作品里已有的同风格图片和风格样张作为风格参考图（`styleReferences`），保持画风一致。
   - `read_work` 读取作品，`write_work` 修改作品，`view_canvas` 截图查看。`write_work` 支持可选的 `view: { claims?, sceneId? }` 参数，保存成功后在同一轮直接等待显影并截图（记为一条独立的 `view_canvas` 步骤，保存失败或同批已有 `view_canvas` 时跳过，`amend` 留存记录自动剥离 `view`），避免模型拆出单独的 `view_canvas` 轮次；`view_canvas` 仍可单独调用（用于局部 `regions`、标注 `annotate` 或交互 `actions`），或放在同轮一个或多个 `write_work` 之后的最后一项（任一保存失败就跳过本轮截图）。`ask_user` 仍需单独调用。没有 `finish` 工具：作者一轮只写文字、没有工具调用时，如果 `Agent.done` 判定可以结束（图片都显影、最新版本看过且没有运行错误），这段文字就是结束语，运行完成；否则把 `done()` 给出的原因作为 "The work is not done yet: …" 消息回给作者。`done()` 把该作品历次运行的观察记录与本次运行的合并后交给 `requireObserved`（仍按各场景当前 `sceneHash` 校验是否干净观察过全图），因此未改动场景的纯问答续轮可以直接结束，不再强迫重跑 `view_canvas`；最小字号低于 `MIN_TEXT`（14 像素，取各场景最新全图的 `Observation.smallestText`）时，`done()` 只检查本次运行的观察记录且每次运行只拦一次，因为地图自带的地名这类字不由作者决定。
4. `write_work` 交给 `modules/workspace` 原子提交。作者和手动编辑写的是同一个 `WorkEdit`（`contracts` 的 `workEditSchema`，语义写在它上方的注释里，`editing/apply.ts` 的 `layOn` 是唯一实现）：`modules`、`links`、`scenes`、`drawings`、`details` 都是按 ID 平铺的表，已有 ID 只改给出的字段，新 ID 就是新增；ID 在整个作品里不重复，已有的部件不用写 `scene`，新部件不写就进当前场景；`bounds` 写成 `[x, y, 宽, 高]`；`data`、`defaults`、`params`、`style` 按键合并（`mergeValue`，RFC 7386：`null` 删除），列表给整个是替换，给 `{"2": {...}}` 是按位置改（位置指这次修改之前的列表，等于长度是追加）；连线的一端是模块 ID（`{moduleId}`，运行时取朝向另一端的边，随模块移动）或 `{moduleId, at}`，`at` 是边或 `[x, y]`；画法的 `source`、场景的 `interaction`、详情的 `html` 可整段写，也可用 `edits`/`interactionEdits` 做 `{find, replace, all?}` 替换（`editedText`：找不到或不唯一就是问题，并给出最接近的一段）；`from` 从作品或库复制一个新画法；`scenes` 另有 `clear`（清空后重构）和 `order`（让列出的模块在它们自己占的层级位置之间换序）；`remove` 最先执行，并连带去掉依赖它的东西（模块的连线和检查、场景的子场景、指向它的跳转），不存在的只在结果里说一句（`notThere`），不拒绝。作者不写 `baseRevision`：运行期间手动编辑一律 409，没有并发；`POST /edits` 的 `{baseRevision, edit}` 才校验版本。提交时把作品新提到的素材从素材库取进作品的 `materials` 快照（库画法只按 `drawingId`、代码字面调用或显式 `materials` 自动取入，避免模块 `data` 里恰好重名的字段值误拉库画法；作品里已有的库画法若在代码里以字符串间接引用则继续保留），不再提到的移出去，已持有的素材保留它取入时的版本（`MaterialUse.version`，素材库更新不会改变已有作品，只有重新取入才换版本；只有还在显影的图片会再取一次），再由 `modules/storage` 写成一个新版本，记下 `Cause`。作者读到的作品（`workspace/author.ts` 的 `forAuthor`）和写的是同一种写法，读到的记录可以原样写回。

   拒绝时一次说全：`readEdit` 把 schema 问题、`layOn` 把落不上的记录、`problemsIn` 把引用不到的东西、`pictureProblems` 把这次改到的部件里不存在的图片、`codeProblems` 把这次改的代码里的语法错误都收进 `EditRejected.problems`（`{at, problem}`，`at` 形如 `links.l-a1.from`）；依赖某条落不上的记录的引用不重复报（`pending`）。作者的写入被拒时 `Context.held` 留住它（工具结果说明留住了哪些 ID），下一次带 `amend: true` 的写入只发改正的部分，`composed` 按 ID 把两次合成一次（`amend` 修正时新传入的 `edits`/`interactionEdits` 替换旧的补丁列表，整段 `source`/`html`/`interaction` 也会清掉旧补丁列表），作为一个版本保存；参数不是合法 JSON 时 `completedRecords` 留住已经完整到达的记录，同样可以 `amend`。不带 `amend` 的写入替换留住的内容。
5. `view_canvas` 经 `modules/observation` 请求截图服务。截图服务用 `modules/runtime/document.ts` 生成页面，加载 `/runtime/runtime.js` 渲染场景，截下图片，作为图片消息送回同一段对话。默认每个场景一张开场全图（加声明的交互检查），没有自动网格局部图；`regions` 按需加最多三张局部，取景框按区域比例定，不发多余画面；同一版本已看过全图且无错误时，局部查看只返回局部。交互检查（`checks`）和 `actions` 是给场景脚本和画法里的按钮用的；一次点击打开了详情页时，截图服务不拍它（详情是作者写的 HTML，由应用排版），而是关掉详情、在结果里写明打开了哪一页（`Shot.opened`，没有 `base64`），点的是模块自己的跳转目标时还提示作者把这条检查去掉，因为跳转不需要代码。运行时页面的详情页是铺满屏幕的一层（`data-drawy-detail`），文章在里面保持自己的宽度；内边距不能加在文章本身上，否则会从它 680px 的最大宽度里扣掉。模块几何只放在全图旁，且只列上次之后变了的（`Context.reported`，压缩时清空）。`figure.smallestText`、`figure.tooSmall`（每个字小于 `MIN_TEXT` 的部件）和 `clippedText` 由 `capture.ts` 的 `readText` 在页面里量出，`tooSmall` 的每项带部件当前的 `size` 和看得清要用的 `sizeThatReads`（不管这段字按 `size` 的几成画），`readableFrom` 说明这个图里多大字号才看得清（`geometry.ts` 的 `opening`），一次写入就能全部改好。开场取景比例 `min(1296/宽, 828/高, 1.5)` 和 `note` 按 0.8 倍绘制写在提示词里，作者第一稿就能按它定字号。`claims` 是作者看图前写下的检查项（时间、方向、比例、因果、数字的条件，图里每条路线和支线都要有），放在截图旁要求逐条核对；核对结果不写给用户，进度说明只一句，因为 Opus 5.5 会把一两句以上的说明作为思考块返回。`Observation.overview` 如实记录这次有没有全图，`requireObserved` 要求最新版本有全图、且最后一次查看没有错误。
6. 运行过程中的每个变化，都以 `run` 事件经 SSE（`/api/events`）推给前端。前端由 `modules/canvas` 把过程画成石墨线起稿和图片显影的动画（没有跟着笔尖走的铅笔）。整个过程同时由 `modules/trace` 记入 `trace.sqlite`。前端右侧的画室（`apps/web/src/Studio.tsx`）把每次运行的步骤按工具分别呈现（每种 `ToolActivity` 一个视图，未知的托管工具走 `hosted`），步骤里不标中间稿的编号，只在运行结束处标出成稿是第几版；预览和恢复在单独的版本面板（`Drafts.tsx`）。用户按提问数版本，不管中间过程：`contracts` 的 `historyOf` 把 `/revisions` 归成当前的版本栈和未保存的手动修改。同一次运行保存的所有稿算一版，空白画布是第 0 版；手动修改存成 `{ kind: "edit" }` 的修订，不算版本，直到用户 `POST /works/:id/save`（`workspace` 的 `saveEdits`）记下一个 `{ kind: "save" }` 修订，把它们收成一版；只有同一次运行连续的修订会合成一版（`sameRun`）；运行开始前留下的未保存修改并入那次运行的版本。恢复是回退：目标是某版结束时的修订，就回到那一版（恢复修订加进它的 `revisions`，之后的版本离开列表，下一版接着它编号，`sealed` 让下一次修订另起一版）；目标是一条未保存的修改，就回到那一步；目标是某次运行中间的一稿，才另记一个 `restore` 版本。每个版本记着创建时下面的版本（`chain`），所以恢复到已离开列表的版本会把它连同下面的一起带回，前端的“撤销回退”和重做就靠这个。修订本身一直追加、修订号不复用，作者的 `Context.known` 不受影响。面板每版一行，未保存的修改在最上面一行（保存、放弃）；打开它时画布放开选区（桌面壳的 `toggle`、手机壳的 `show`），因为版本是整体看的。点一行在画布上预览，“回到此版”按钮一直可见；`versionOf` 把修订号换成版本号，画室的成稿、预览条、回退后的提示和左侧栏都用它（`WorkProgress.unsaved` 是未保存的修改数）。撤销（`stepBefore`）有未保存的修改时退一步修改，否则退到当前版本的上一版。输入框（`Composer.tsx`）一直在页面下方，输入框文字在上、工具在下一行（左起方形的添加按钮、档位方签，右端风格和墨色方形的发送），模型选择 `ModelBar` 就是那枚档位方签（档位名加剩余次数），`engaged`（运行中或等待回答）时不显示模型选择；作者运行中（`collapsed`）输入框收起成一条，只有当前进度（`Now`）和停止按钮，等待回答时展开；作者开始运行时画室自动打开。输入框上方的 `unsaved-bar` 提示未保存的手动修改（保存、放弃，⌘S 保存），手动编辑面板开着时不显示（`Bars` 的 `editing`），只留标题牌版本印旁的蓝点，免得连续修改时一直提示；有未保存的修改时发请求，会话的 `send` 先把请求挂起（`holding`），让用户选保存后发送、放弃后发送或取消（`decide`）。回到某版和放弃修改后，提示条上可以撤销（会话的 `back`，⌘Z 也走它）。预览版本、回到当前和回退都把修订号放进 `own`，画布安静替换，不重播落笔动画。画室、草稿和编辑面板宽度分开（桌面壳的 `panelWidths`，`--journal`/`--drafts`/`--edit`），由 `Resizer` 拖动并按面板记在 `localStorage`。用量由 `Studio.tsx` 的 `spentBy`/`Stats` 按 `costOf(run.usage, run.prices)` 算出：运行标题行右侧的费用按钮展开这次的卡片（费用、token 与缓存命中、耗时、搜索、图片几块数字，按服务分色的费用构成条，每个服务一行），画室顶部的累计行展开整个作品的同样卡片。回复用 `Markdown.tsx` 渲染，`tidy` 去掉模型留下的 `\ue200…\ue201` 引用记号并移动引用位置。

托管工具（模型服务方自己执行、输出项类型以 `_call` 结尾的，如 `web_search_call`）在 `agent/steps.ts` 的 `LiveSteps` 里统一处理：成为运行步骤（`web_search` 有专门的活动，其余是 `{ name: "hosted", tool, detail }`），按 `run.usage.hosted` 计数，并用 `tracer.record` 记成所在轮次下的 `tool` 记录（`attrs.hosted`、`args` 是动作、`output` 是原始项）。`trace` 的 `meters` 按 `attrs.meter`、工具名或种类汇总次数、耗时和 token，所以新增工具不用改 trace。`run.usage` 累计每轮和压缩的 token、托管工具次数与生图用量（`images` 从图片接口返回的 `usage` 取）。搜索是否合理由 `prompts.ts` 的 `# Research` 一节约束，`set_brief` 和 `view_canvas` 的结果在本次运行搜索过时附上 `research`（次数、打开过的网页），提醒作者按已有来源判断。硬预算在 `agent/spending.ts` 的 `steering`：每次请求 `SEARCH_LIMIT` 次、第一稿保存后 `SEARCH_AFTER_DRAFT` 次，预算内的轮次带 `max_tool_calls`，用完后带 `tool_choice: allowed_tools`（只列函数工具）；两者都不改 `tools`，所以不破坏缓存前缀，不要改成增删 `tools` 的做法。轮次的 trace 在 `request.steer` 里记下这次的限制。

导出：`/api/works/:id/scenes/:scene/picture`（PNG，`?format=pdf` 为一页矢量 PDF，截图服务 `render` 的 `format`；画面由 `Canvas.crop` 裁到场景内容的边缘，不留纸边，便于当壁纸或插进文档），`/page` 是可离线打开的单文件交互网页（`runtime/document.ts` 的 `standaloneDocument`：内嵌 `dist/runtime/runtime.js` 和作品图片；SVG 以文本 data URL 内嵌，`scene.ts` 在它上面替换 `currentColor` 完成着色；详情 HTML 和画法代码里写成地址的 `/materials/files|thumbs/…` 也连同查询串整个换成 data URL（`color` 交给素材库着色、`size` 定缩略图大小，HTML 里的 `&amp;` 也认），SVG 的引号和括号一并转义；以 `/` 开头的 fetch 改到导出时的站点，`/materials/geo` 因此带 `Access-Control-Allow-Origin: *`）。JPG、社交卡片、复制和系统分享在前端由 PNG 生成（`Export.tsx`）。剪贴板和系统分享要在点击的临时授权内调用，截图可能要好几秒：复制在点击时立即 `clipboard.write`，传入图片的 Promise；分享不能等，所以菜单一打开就开始截图，图好之前分享项显示准备中，点击时直接 `share`。Excalidraw 和 Mermaid 两种可编辑格式完全在前端生成（`interchange.ts` 的 `excalidrawOf` 与 `modules/interchange` 的 `toMermaid`），不经截图服务：Excalidraw 要的部件图片从页面上的画布（`[data-canvas]`）里按模块 ID 取，所以导出的是当前显示的场景；复制到 Excalidraw 写的是它的剪贴板格式 `excalidraw/clipboard`。

## 创作、搜索与生图的组合

模型配置的结构是“规格 + 适配器”，新增接入方式、接口格式或搜索服务商都是加条目，读它们的代码不改：
- `contracts/models.ts`（由 `contracts/index.ts` 转出）是唯一说明“谁能做什么”的地方：`channelSpecs`（`api`/`oauth` 各自的固定地址、能说的接口格式、速度档、能否内置搜索、能否固定提供商、要不要 Account ID）、`protocolSpecs`（每种接口格式的官方地址、能否内置搜索、是否有速度档）、`searchProviderSpecs`（地址、是否必须有 Key、是否由服务商读网页）。`settleWriter`/`settleProvider` 按规格改正模型（格式不被支持时退回接入方式的第一种、内置搜索不能用就不开放、可选速度只留连接和格式提供的、默认档位取可选的），`modelCatalogSchema` 和设置页都用它；`reconnect` 在供应商换接入方式时把地址换成 `endpointFor` 给的地址。`offersBuiltinSearch`、`speedsOf`、`pinnedProvider`、`searchReady`、`protocolFor`（新模型按地址猜格式）都从规格推出。`picked`/`settingsFor`/`menuFor` 是“用户选了哪个档位、落到哪个组合”的唯一实现，`UserStore.settings()` 和 `/api/models` 只调用它们；`costOf` 是费用的唯一算法，前端账单和运行记录都用它。
- `modules/models` 每种格式一个适配器（`responses.ts`、`chat.ts`、`anthropic.ts`、`interactions.ts`，接口见 `types.ts` 的 `Adapter`），在 `index.ts` 的 `adapters: Record<Protocol, Adapter>` 里登记。`generate(role, turn)` 收一个 `Turn` 对象（`instructions/input/tools/signal/onEvent/budget/cacheKey/steer/effort`），先做通用处理（凭证检查、`blind`、输出上限），再交给适配器。按格式不同的行为都问适配器：`effortControl`（`request` 每次请求带档位、`conversation` 在对话里插 `configuration_update`、`fixed` 只能改请求级强度）决定 `agent` 的 `withLessThought` 和 `holdEffort`；`narrow` 决定 `steering` 能否不改工具列表就收窄（Responses 与 Interactions 有）；`describe` 给 trace 的 `request` 补字段（Responses 与 Interactions 的 `serviceTier`），由 `requestOf` 合成。`http.ts` 放共用的 `headers`、`post`（自动带 `pinnedProvider`）和 SSE 读取 `events`。`agent` 里不再出现按 `protocol` 分支的代码，加格式时也不要再加。
- `modules/search` 的 `clients: Record<SearchProvider, Client>` 每个服务商一项：`search`，以及服务商自己读网页时的 `read`（没有就由 DrawY 直接读）。
- 设置页 `apps/web/src/ModelSettings.tsx`：`WriterSection` 和 `ImageSection` 共用 `ProviderSection`（供应商列表，展开是连接字段和它的模型列表；两者的差别写成一个 `Kind`），`SearchSection` 列搜索服务并设默认联网方式。添加供应商从 `presets` 起步；默认模型不能删，它所在的供应商也不能删。`ConnectionFields` 按规格只显示适用的控件（Account ID），模型的格式、固定提供商、可选速度和缓存写入价格只在适用时出现。价格用 `NumberField`（文字输入、保存数字）。行、分组、条目这些通用部件在 `SettingsParts.tsx`，账号、邀请和角色这类管理列表都经它的 `useLoaded`（读取、出错、`attempt` 执行修改并报告错误）和 `Loaded`（错误、加载中、内容）。设置读到的东西按名字留在 `SettingsParts.tsx` 的 `kept` 里（`own`：本人偏好和模型目录；`accounts`：账号和角色，账号页和角色页共用；`invites`），再打开时先显示留着的、同时重新读取（`read` 合并同时发出的读取；读取期间本页改过的不被覆盖）；`Settings.tsx` 的 `readSettings` 按权限预先读这些，在账户菜单打开时和设置页打开时调用，所以打开设置和切换各栏都不用等网络。退出登录时 `forgetSettings` 清空。凭据输入框是普通文本框，明文显示。档位页（`LabelSection`）在标题行标出不可用的档位并列出原因；强度和速度用 `ChooseOrDefault`，第一项是“模型默认”，速度列出连接支持的全部档位（只开放一个时也能选），选了模型没开放的速度就同时改那个模型的 `speeds`（`offering`）；档位可上移下移（即菜单顺序）、复制、设为默认。模型条目标出用到它的档位，可复制。新的接入方式、格式或服务商要在 `i18n.tsx` 的 `settings.channels/credentials/protocols/protocolHints/providers/providerHints` 补中英文，类型检查会提示缺哪一项。

`ModelCatalog` 里三样东西分开配置：`writers`（绘制供应商，每个 `Provider` 是连接加 `models: WriterModel[]`）、`painters`（生图供应商，`models: ImageModel[]`）、`searches`（搜索服务），外加对所有档位生效的决策模型 `judge`（`Judge`：开关、接口地址、密钥、模型、问题、每百万输入 token 单价，管理员在设置的“评选与核对”页配置；旧目录没有它时 `judgeSchema` 用 `defaultJudge` 补上关闭的默认值；`judgeReady` 要求开启且有密钥，`settingsFor` 这时才给 `Settings.judge` 和 `RunPrices.judge`，`run.services.judge` 记模型名，`costOf` 单列 `judge`）。用户只能选“档位”（`labels: ModelLabel[]`，管理员在设置的“档位”页配置）：每个档位有名称、说明，以及绘制模型、可选的强度和速度（不填用模型默认）、搜索方式 `web` 和生图模型；`modelCatalogSchema` 校验档位引用的模型和搜索都存在、ID 不重复、`defaults.label` 是其中之一。没有配置档位时 `labelsOf` 用 `defaults: { writer, image, web }` 合成一个 `default` 档位，所以 `defaults` 仍是"未配置档位时的组合"，也是新档位的起点。被档位用到的模型和它所在的供应商在设置页不能删。模型 ID 在同类里全局唯一；显示名默认是 `writerLabel`/`imageLabel` 给的 `模型[供应商]`（固定了 OpenRouter 提供商时是 `模型[供应商/提供商]`），填了 `name` 就用它。`WriterModel` 记管理员开放给用户的 `efforts`/`speeds`/`builtinSearch` 和各自的默认 `effort`/`speed`，以及价格 `prices`（每百万 token 的 `input/cached/cacheWrite/output`、内置搜索每次 `search`）和速度倍率 `speedRates`（缺省取 `speedRates` 常量）；`ImageModel.prices`（`ImagePrices`）是每张图，以及 Images API 分开计价的 `textInput`/`imageInput`/`output`/`textOutput` 每百万 token：`imageTokensOf` 按响应里的 `input_tokens_details`/`output_tokens_details` 拆开（不拆的服务商全算文字输入），`run.usage.images` 分别累计，所以带风格参考图的生图按图片输入价计算；`SearchService.prices` 是每次查询和每次读网页。存的目录读不通时 `Storage.models()` 换成 `defaultCatalog()`，不做旧格式迁移。`UserSettings` 只记 `preferences` 和 `label`（可为空）；`PUT /api/settings` 用 `settingsChangeSchema` 接收，其他字段丢弃。`picked` 落定：档位不在了用 `defaults.label`，再不在用第一个；强度取模型可选里最近的，速度不可选就用模型默认；`web` 是 `off`、`builtin` 或搜索服务 ID（服务 ID 不能叫这两个名字），经 `webFor` 落定——要内置搜索而模型没有、或服务没有 Key 时是 `off`。`UserStore.settings()`（即 `settingsFor`）合成 `Settings`：`label`（档位名）、`author`（运行时的 `Role`）/`authorName`、`search: { mode, service? }`、`image`/`imageName`，以及这次的 `prices`（`RunPrices`：按速度倍率换算后的 token 价格、按搜索方式取的每次搜索和读网页价格、生图价格）。

运行时的 `Role` 是供应商连接加所选模型和选项：`protocol`（`responses`、`chat` 或 `anthropic`，ChatGPT OAuth 只能是第一种）、`vision`、`tools`、`effort`/`speed`（用户选的）、`efforts`（模型开放的档位，可以有 `max`）、`maxOutput`。适配器只读 `Role`，不知道目录的形状。`models/index.ts` 的 `generate` 对外只说 Responses 的格式：`protocol: "chat"` 时由 `chat.ts` 把 Responses 项转成 Chat Completions 消息（`toMessages`：同一轮的函数调用合成一条 assistant 消息，夹在调用结果之间的图片消息挪到结果之后，`configuration_update`、托管调用和加密推理丢掉），再把流式块转成同样的事件和项（`reasoning_content` 存成 `{ type: "reasoning", reasoning_content }`，Responses 请求会滤掉它）；不能看图的模型由 `blind` 把图片换成文字。Chat 请求没有 `prompt_cache_key` 和 `tool_choice`，思考强度按请求传 `reasoning_effort`（取 `turn.effort`），所以 chat 适配器的 `effortControl` 是 `request`，不插 `configuration_update`。

`protocol: "anthropic"` 由 `models/anthropic.ts` 的适配器用官方 `@anthropic-ai/sdk` 调 Messages 接口（`baseUrl` 是 `https://api.anthropic.com`，末尾的 `/v1` 会去掉；SDK 不重试，重试交给 agent，错误转成 `模型请求 <状态>` 的说法）。`toAnthropic` 把 Responses 项转成消息：同一轮的模型项合成一条 assistant 消息，调用结果放在下一条 user 消息最前面，结果之间的图片和 `configuration_update` 挪到结果之后；没有工具的请求（压缩摘要）把调用和结果写成文字。Claude 返回的每个项都在 `anthropic` 字段里留着原始内容块（签名的 thinking、带 citations 的 text、tool_use、`server_tool_use` 加搜索结果），下次原样发回，因为较新的模型会校验 thinking 所在的对话前缀；`forResponses` 在发给 Responses 时去掉这些块、Claude 的 thinking 和它自己的搜索，`toMessages` 本来就忽略它们，估算上下文时 `anthropic` 也不计。请求固定带 adaptive thinking（`display: "summarized"`，摘要作为思考步骤显示）、`output_config.effort`、系统提示词和最后一个工具上的 `cache_control` 以及顶层自动缓存；有工具的请求还由 `withTurnBreakpoint` 在模型上一轮最后一个 text 或 tool_use 块上放一个断点（发送时复制，不改存下的块）：缓存只往回找 20 个位置，一轮新增太多内容块时顶层断点够不到上次的缓存，会退回系统前缀整段重写。四个断点已用满，不要再加。函数工具带 `eager_input_streaming` 让画布边流边画。按模型版本（`claudeVersion` 同时接受 `5-5`、`5.5`，以及提供商前缀和日期后缀）加 beta：`perTurnEffort`（Opus ≥ 5、Sonnet/Haiku ≥ 5.5、Fable/Mythos ≥ 5.1）时 `configuration_update` 变成只带 `output_config.effort` 的 system 消息，其他 Claude 模型的强度只能在请求级改；thinking 与对话绑定的模型带 `block_binding: drop_block`，`withoutOldPictures` 之类改写历史时只丢掉失效的 thinking；不带 `fallbacks`：被拒答的轮次不换模型续写，运行以“模型拒绝了这一轮的内容”失败（不重试），已保存的版本保留。内置搜索是 `web_search_20260209`（4.6 以前的模型用 `web_search_20250305`），每次请求 `max_uses` 8 次，`server_tool_use` 和结果合成 `web_search_call` 项，所以步骤、计数和 trace 与 OpenAI 的一样；Messages 没有不改工具列表就收窄工具的办法，适配器没有 `narrow`，`steering` 对它返回空，画出第一稿后的搜索预算只对独立搜索生效。`pause_turn` 在适配层里接着请求；`max_tokens`、`refusal` 和中途断开都按失败处理。工具参数开了 eager 流式，接口不校验，模型可能写出坏 JSON，走 OpenRouter 也没有语法保证（`strict` 不生效）。SDK 的 `.stream()` 遇到坏块就放弃整个流，所以适配器用 `messages.create({stream: true})` 读原始事件、自己累积内容块：坏参数包成 `{INVALID_JSON: 原文}` 留在对话里（Messages 只收对象），项的 `arguments` 仍是原文，用量也完整。`call` 解析失败时按普通工具失败回给作者，由它改正后重发，不用重来一整轮的思考；原文留在 trace 的 `args` 里供分析，同批的 `view_canvas` 被跳过。其他格式的坏参数走同一条路。

一次运行只有一种搜索：`toolsFor(settings)` 在 `builtin` 时加托管 `web_search`，`service` 时加 `tools.ts` 的 `searchTools`（函数 `web_search {queries}` 和 `open_page {url}`，由 `modules/search` 调服务商：DeepSeek 的 `/search`、`/fetch`，Tavily 的 `/search`、`/extract`，Brave 和 SearXNG 只搜索、网页由 DrawY 直接读取并去掉标签），`off` 时都不加。两种搜索都记成 `web_search` 步骤（`open_page` 的 `action` 是 `open_page`），所以 `searchesLeft`、`research` 不分来源；独立搜索的预算在执行时检查，按查询计（`cost`：服务商每个查询收一次费，一次调用带几个查询就算几次；读网页和托管搜索按调用算一次），剩下的不够时只问前面几个查询、结果里用 `notAsked` 列出没问的，预算已用完就去掉这一步并回报搜索已关闭（`research` 对独立搜索给 `searchQueriesLeft`，托管搜索给 `searchCallsLeft`），Responses 协议下用完后还会带 `allowed_tools`（排除两个搜索函数）。`run.usage.searches/pages` 计搜索和读网页次数（托管搜索按 `action` 分，独立搜索的 `searches` 按实际问过的查询数），`run.usage.cacheWrite` 记 Claude 的缓存写入（适配器在 `input_tokens_details.cache_write_tokens` 报出）。`run.services` 记下这次的绘制模型、强度、速度、搜索方式和服务、生图模型的名字，`run.prices` 记下开始时定下的价格，费用是 `costOf(run.usage, run.prices)`，之后改价格不影响已有运行；`/api/traces` 和 `/api/traces/:id` 给每条记录附上对应运行的 `cost` 和 `services`。前端 `Studio.tsx` 的 `spentBy` 只读 `run.usage`，`WorkUsage` 显示作品累计。

模型服务报的错用 `http.ts` 的 `readable` 换成它自己的话（错误对象的 `message` 加 `code`），不把 JSON 原样给用户看：HTTP 错误仍是 `模型请求 <状态>: …`（`transient` 据此决定重试），流里的错误由 `streamError` 按代码分：限流、服务端错误记成对应状态以便重试，其余（额度用完、拒绝请求）是 `模型服务报错：…`，不重试。回复和失败说明在 `Now` 里只显示前两行：限行写在按钮里的 `span` 上，因为 Safari 不对按钮本身限行。作者的结束语只说作品给读者看什么、怎么点开看，不写检查结论（提示词里写明了原因：手机上这段话会盖在画上）；截图旁的 `claims` 说明也要求只在思考里核对、不写进进度和结束语，因为原来的“说出每条是否成立”会让模型把“三项都成立”写给用户。

失败的模型尝试单独计费：`turn` 把每次没完成的尝试（断流、截断、取消）记入 `run.usage.failed`（次数、耗时含等待、输入、缓存、输出），不算进 `input`/`output`；工具参数写坏计 `invalidCalls`（用量在写它的那一轮里，这里只计次数）；生图失败另计失败张数；模型已成功返回的每次图片（包括抠图重画前被弃用的图片）都计入 `run.usage.images` 的张数和 token，后续重试失败也保留已产生的费用。Claude 适配器在流开始和 `message_delta` 时发 `response.usage` 事件报告已知用量，断开时输出没有上报，就按已流式到达的字符数除以 3 估算（`estimated`，不含未显示的思考，所以偏低）；其他格式断流时输入也未知，只有输出估算。`costOf` 单列 `failed` 并计入 `total`，账单在有失败时多一行，失败尝试也作为 `attrs.failed` 的 `turn` 记录进 trace，所以 `meters` 和 token 合计都包含它。

上下文达到 20 万 token 时 `compact` 把对话换成摘要。大小取上一轮 `usage.input_tokens`（记在 `Context.measured`）加之后新增项的估算，估算不计 `encrypted_content` 和图片 base64；摘要请求沿用作者的系统提示词、工具和缓存键，把总结要求作为最后一条用户消息追加在原样的对话后面，所以整段对话从缓存读取；强度在对话里改变的格式在总结要求前追加一个最低档的 `configuration_update`，其余格式在请求上降到 low（会让缓存失效）；输出上限 16k，不设 `tool_choice`（在 Anthropic 上它会让对话缓存失效），作者没写出文字时按失败处理。替换后的对话依次是偏好、摘要和整份作品。摘要失败时只把较早的截图换成文字占位，运行继续。

## 账号、角色与模型

账号的角色记在 `users.role`，角色在 `roles` 表（`storage` 的 `roles/role/saveRole/deleteRole/account/accounts/setRole`，`identity` 的 `saveRole/removeRole` 做校验）。权限清单是 `contracts` 的 `permissions`：`models.manage`、`materials.all`、`materials.manage`、`accounts.manage`。内置角色 `admin` 读出时永远拥有全部权限（以后新增的权限也自动有），不能修改；`member` 是新账号的默认角色，权限可改、不能删；删掉自建角色时它的账号变回 `member`。第一个注册的账号是 `admin`；`setRole` 不允许去掉最后一位管理员。

注册要邀请码：`identity.signUp` 在库里还没有账号时直接注册（第一个账号设置站点），之后要求一个未使用的邀请码，建账号和标记邀请码已用在同一个事务里，注册失败（比如用户名重复）邀请码仍可再用。邀请码存在 `invites` 表（`storage` 的 `invites/addInvite/useInvite/deleteInvite/hasAccounts`），由 `createInvites` 生成 `XXXX-XXXX` 形式、不含易混字符的码，输入时 `inviteCode` 忽略大小写、空格和连字符。管理接口 `/api/admin/invites`（列出、生成 `{count}`、删除未使用的）要 `accounts.manage`；已用的邀请码不能删，留作谁凭它进来的记录。注册页先问 `GET /api/auth/signup`（不需登录）是否要邀请码。`identity.register` 本身不查邀请码，供测试和内部直接建账号。

作品标题：用户重命名（`store.rename`）会在作品上记 `named: true`，之后作者运行里的 `write_work.title` 和第一次简报都不再改标题（`writeWork` 返回 `keptTitle`，工具结果里告诉作者），撤销、恢复也保留它。这条规则只出现在工具结果里，不写进系统提示词或工具说明，保持缓存前缀不变。生成图和上传图的 ID 先截断再去首尾连字符；`take` 的 `ID`/`QUOTED` 正则接受 `--`，兼容以前生成的 ID。服务端用 `app.ts` 的 `allowed(c, 权限)` 拦截，管理接口都在 `/api/admin/*`；前端用 `account.tsx` 的 `useCan()` 决定显示什么，但它只是界面，权限以服务端为准。新加权限时要补 `permissions`、`i18n.tsx` 的 `settings.permissions/permissionHints` 中英文，以及服务端拦截。

输入框工具行里、添加按钮右边的 `ModelBar` 是一枚填色的小方签：档位名（多于一个档位时可点开选择）加灰色的剩余提问次数（`quotaShort`）。选了之后前端先用 `chosen()` 乐观显示，再 `PUT /api/settings` 并重新读 `/api/models` 看落定结果。模型名、地址、凭证和价格只在设置中显示。

对没有 `models.manage` 的账号，服务端用 `app.ts` 的 `showRun` 把运行的 `services` 换成只有档位名（`/runs`、开始/回答/取消的返回和 SSE 的 `run` 事件都经过它），运行记录 `/api/traces/*` 只给 `models.manage`，前端也只在有这个权限时显示运行记录入口和账单里的模型名。读作品和运行的接口（`GET /api/works`、`/api/works/:id`、`/api/captures/:id`、`/api/traces`、`/api/traces/:id`、`/api/traces/:id/spans/:span`）经 `app.ts` 的 `readable`：带 `?account=` 且不是本人时要 `accounts.manage`，读那个账号的数据（作品按它的 `viewer` 取素材）；`/api/traces` 另可带 `?work=` 只列一件作品的运行。运行记录页（`TraceView.tsx`）据此让能管理账号的人在顶部选账号，在“运行”和“作品”两个列表间切换：作品用 `home/LiveWork.tsx` 只读地现场画出（能进子场景），下面列它的运行，点开回到运行的时间线；地址带着 `?account=`，刷新后还是那个账号。写入接口不认 `account`，只改本人的作品。素材的列表、详情、发布和上传响应统一经 `showMaterial`：没有 `models.manage` 时省去 `origin.model`，素材库里的生成来源仍完整保留。

提问次数：`users.quota`（`Account.quota`，`null` 为不限）。新账号是 `DEFAULT_QUOTA`（10），第一个账号不限。`POST /api/works/:id/runs` 先 `spendQuota`（原子地减一，用完时 403“提问次数已用完”），`agent.start` 失败就 `refundQuota` 退回；回答作者的问题（`/runs/:id/answer`）不扣。管理员在设置的“账号”页逐个改（`PATCH /api/admin/accounts/:id` 的 `{quota}`，可与 `role` 分开）。前端用 `user.quota` 显示剩余并在为 0 时禁用发送（等待回答时仍可回答），发出新请求后在本地减一。

空白画布（`/new`，首页的“从白纸开始画”和侧栏的“新建空白画布”都通向它）直接渲染创作页（`App.tsx` 的 `blankSession`，ID 为 `_blank` 的本地 `WorkSession`，不提前在服务端建作）。未登录访客进入 `/new` 时不拦截整页，可浏览画布、开关面板、切换语言或在输入框里写提示词；真正使用需要账号的功能时（发送创作请求、上传/拖放/粘贴图片、打开素材库、在画布上手动编辑或重命名、或直接访问需登录的路由）再弹出 `Auth.tsx` 的 `AuthDialog`（带 `auth.why*` 上下文原因），登录或注册成功后保留输入并自动续接原操作（`pendingAuth` / `pendingMaterialize`）。对 `_blank` 的编辑或重命名通过 `SessionHost.materialize` 物化：若未登录则先等待 `AuthDialog` 完成（取消则返回 `undefined`），登录后再调用 `POST /api/works` 创建真实作品、切换路由到 `/a/:id` 并执行一次编辑或操作（`ops.ts` 的 `ensureReal` 在调用 `/api/materials` 前先物化，`edits.ts` 与 `revisions.ts` 在提交前物化）。已登录用户在 `/new` 发送请求同样按此物化并跳转到 `/a/:id`；首页输入框在 `_blank` 状态下保留风格选择与清除（`WorkComposer` 传 `style`/`setStyle`）。`Auth.tsx` 抽出共用的 `AuthForm`（密码框右端带显示/隐藏按钮，注册在需要邀请码时附 `auth.inviteHint`），供 `AuthDialog` 与 `Auth` 共用；`Home.tsx` 仍保留原文件列表组件定义但不再挂载于 `/`。左侧栏（`Rail.tsx`）对未登录访客同样显示，底部为“登录 / 注册”入口，手机端在 `/` 点顶栏返回可打开侧栏。最近作品每项在标题下有一行状态，来自 `/api/works` 的 `progress`（`UserStore.progress`：最近一次运行的状态和提问开头、`historyOf` 算出的当前版本号、是否空白）——正在绘制、等你回答、上次没有画完、已停止，或“第 N 版 · 时间”。收到 `run` 事件时前端先就地改状态，运行结束再重读列表。

绘制模型的可选 `provider` 保存 OpenRouter 提供商标识。设置页的“固定提供商”留空时自动路由，填写后 Responses、Chat Completions 和 Messages 都传 `provider: { only: [标识], allow_fallbacks: false }`；不能切到其他提供商，渠道不可用时返回错误。轮次的 `request.provider` 同样记录这个限制。

模型配置全站共用：`ModelCatalog` 存在 `system` 表，只有 `models.manage` 能读写（`/api/admin/models`）。每个用户自己只存 `UserSettings`（长期偏好和档位），`/api/models`（`ModelMenu`）只给出每个档位的 ID、名称、说明、是否可用（绘制模型已接入且能调工具），以及落定的档位，不给模型、凭证和价格。`UserStore.settings()` 把这两者合成运行要用的 `Settings`，`agent` 和 `images` 只读这个结果。

## 前端的分层

`apps/web/src` 分三层。作品页可以按设备换成完全不同的界面，会话逻辑不用重写：

- **App**：`App.tsx` 管这些：
  - 路由（`routes.ts` 的 `pageOf`/`workIdOf`/`sceneOf`/`addressOf`）；
  - 删除与撤销删除、素材库对话框。侧栏的作品列表由每个登录账号自己的 `Recents` 缓存。首次展开时读取 `/api/works?covers=0`；收起时卸载作品行，保留数据和滚动位置。创建、保存、改名或运行状态切换时，服务端经 SSE 推送该作品的最新摘要。连续的流式步骤沿用同一运行状态；删除事件移除对应行。重连时同步整表，侧栏收着就推迟到下次展开；同步期间收到的事件在快照上重放。管理页切到「作品」标签时才取带封面的列表。
  - 正在写的请求（`session/request.ts` 的 `RequestDraft`，一个 store：文字、附件、上传中的数量、主页选的风格、问题的选项；`hand` 把要作者做的修改写进去，并让输入框取得焦点）。请求草稿用 `Store` 的 `immediate` 通知，在输入事件里同步更新 React 的受控输入框；不能延迟到微任务，否则 React 会先恢复旧值并打断输入法组词。请求跨页面存在，因为在素材库里选的素材、主页发出的请求都要带到作品页。附件带着素材各语言的名字，由显示的地方挑。
  - 提示：`feedback.ts` 的 `Feedback` 也是一个 store，记着最近的错误和提示，并按时收起；`SessionError` 的措辞也在这里，供不自己措辞的页面使用。

  App 不读会话的快照（只有 `OpenWork` 读作品到了没有、打开失败没有），所以作者运行时的事件不会让 App 重新渲染。作品页的壳由 `shells.ts` 选出，App 交给它 `ShellProps`（`shell.ts`），只有每种壳都确实需要的四样：
  - `session`：会话本身（store 加动作）；
  - `asking`：`draft`、`send`、打开素材库的 `pick`、档位和 `choose`，以及 `blocked`（没接入模型或提问次数用完；等待回答时仍能回答）。`send` 检查完上传和 `blocked` 后交给会话；在主页没有打开的作品时，`send` 先建作品、用 `begin` 打开，再发出；
  - `feedback`；
  - `go`：去另一个地址。

  这四样在作品页打开期间保持同一个对象（`asking` 只在档位或 `blocked` 变化时更换），`shells.ts` 又给每个壳包了 `memo`，所以 App 因作品列表等原因重新渲染时，作品页不跟着渲染。账号从 `AccountContext` 读（`useAccount`/`useCan`），没接入模型的提示是 `Composer.tsx` 的 `Unconnected`。
- **会话层** `session/` 不含 JSX、样式和界面文案，不碰 DOM；本地存储只经 `storage.ts` 的 `stored`/`store`（没有浏览器或被拒绝时什么也不做）。`work.ts` 的 `WorkSession` 是一个外部 store，由六个各管一件事、各有自己状态的部分组成，共用一个 `Context`（`types.ts`）：
  - `revisions.ts`：作品与修订。服务器推来的作品比当前的旧就不采用；修订号变了就重取 `/revisions`，预览随之结束。它还记着哪些修订是用户自己的（`own`、在路上的请求），由 `quiet` 回答；`look` 管预览，`rename` 改标题。
  - `runs.ts`：运行与 SSE。自己经 `events.ts` 的 `listen` 订阅，同一用户的所有订阅共用一个连接（各标签页用 Web Locks 选一个去听，经 BroadcastChannel 转给其他页）。手机会冻结不在前台的页面，流会无声地断掉，持锁的后台页还会一直占着锁，所以只有显示着的页面去听：页面隐藏时放下流和锁，重新显示（`visibilitychange`、从往返缓存回来的 `pageshow`、`online`）时重新打开，新流以 `connected` 开头，于是补取错过的东西；服务器每 20 秒发一次 `ping`，`QUIET`（45 秒）内什么都没收到就当流已死、重新打开。SSE 响应带 `X-Accel-Buffering: no` 和 `Cache-Control: no-transform`，前面有代理时也不被攒着发。`offline` 和打开失败的 `unopened` 也在这里；收到 `connected` 时重取作品和运行，用 `merged` 合并。打开作品时先显示作品，运行历史随后合并，`loaded` 之前不能发送、不能手动编辑。`earlier` 是打开作品时已经结束的最后一次运行，它的回复留在画室，不在画布下面重复显示。
  - `edits.ts`：手动修改的队列与草稿（`commit` 返回保存后的作品，`change` 只返回有没有修改）。
  - `sending.ts`：发送与挂起。有排队中或未保存的手动修改时挂起请求，等 `decide("save"|"discard"|"cancel")`；真正发出后调用 `Ask.sent`。请求关于什么由调用方给（`Ask.focus`：选中的模块或连线），`aboutOf` 把它写在请求后面（写给作者的，不是界面文案）。
  - `versions.ts`：保存、放弃、回退（`back` 记着回到第几版或放弃了修改，十秒内可以撤回，此时 `undo` 先撤回回退）、撤销（服务端 `/undo` 按版本回退；没有重做）。
  - `scenes.ts`：地址里的场景（`locate`），地址里的场景不存在时换回根场景的地址；`enter(id, asking)` 进入场景，场景还是空的就用壳给的 `asking(标题)` 作为请求请作者画；一次运行只在别的场景画了东西时，结束后跟过去（`follow`）。

  会话只说发生了什么，怎么说、怎么呈现由壳决定：拒绝或做不到时抛 `SessionError`，它的 `reason` 是 `noScene`、`busy`、`linkDrawing` 或 `imagesOnly`；事后要告诉用户的事经 `on(listener)` 发出 `Happening`（`saved` 带版本号；`failed` 是开始后就不再等待的操作失败了）；快照里的 `back` 是结构化的。服务器的错误原样传出，服务端已经按请求的语言翻译好。`SessionHost` 只剩跳转地址、刷新列表、扣提问次数、订阅事件，以及作品内容用的语言（`locale`：从素材库取进作品的名字用哪种语言）。

  动作是会话对象自己的方法（`session.save()` 等，构造时绑定一次）。快照只有数据，`build` 只在被读到时才重建（`Store.changed` 默认标记过期，并在本轮结束时通知一次；请求草稿按上述规则立即通知），没变的字段沿用上一份快照里的同一个对象（`kept`）。组件用 `useSelect(store, 选择器, 比较)` 只读自己显示的那一片，默认按浅比较，选出的值没变就不重新渲染。这一点必须保持：作者运行时每秒会有很多 `run` 事件，低端手机上也要跑得动。`session/work.test.ts` 换上假的 host 和内存里的假服务器，验证草稿、安静替换、挂起、请求附带的选区、回退与撤销、重做、预览、迟到的旧作品、等模块画出再选中、跟随场景、拒绝的理由和发出的事、一轮变化只通知一次且没变的部分保持原对象。
- **会话与画布的边界**是 `View`：会话只用 `center()`、`scale`、`select(ids)` 和 `drawn(ids, revision)`。`Canvas.drawn` 不计时：模块真正画出来（不只是排好位置）就是 `drawn`；画过一个不比 `revision` 旧的版本、里面却没有这些模块，就是 `missing`；画布先没了就是 `gone`。慢设备只是等得久一点，不会误判。壳经 `attach` 把 `Canvas` 交给会话。反方向由画布问会话：`quiet(revision)` 为真就原地安静替换。

  `session/ops.ts` 的 `editOps` 是与设备无关的手动操作，作用于调用方给的模块或连线（删除、复制、排序、编组、对齐、移动、连线、拷贝出 `Clip`、粘贴，放文字、图片或库画法；新文字的内容由调用方给）。它们都经 `edits` 提交；新做出的模块等到 `drawn` 后才选中；失败作为 `failed` 发出。`session/clip.ts` 的 `Clipboard` 记着最后拷贝的内容，并经 `storage.ts` 的 `stored`/`store`（浏览器拒绝本地存储时什么也不做）留给别的标签页。
- **壳的选择**：`shells.ts` 里只有两个壳：`phone` 和 `desktop`，各按需加载。`PHONE` 查询只看宽度和 `pointer`，不看 User-Agent，匹配就用手机壳，否则用桌面壳。窗口变化时跟着重新判断（`useShell`）。用户可以在账号菜单里依次换成“自动”或某一种，选择记在 `drawy.shell`。每个壳由 `React.lazy` 单独分包，在 `Suspense` 里加载，并包了 `memo`。

  设备怎么分：
  - `phone`（`PHONE`）：窗口窄于 600px（竖拿的手机，或被拉得很窄的电脑窗口），或者触屏且高度不到 500px（横拿的手机）。
  - 其余都用 `desktop`：平板（短边 600px 以上，竖拿横拿都是）、触屏笔记本和电脑。理由有三：平板放得下画布加一块侧面板；人们在平板上仍会用手指或笔排版；桌面壳里每个操作都有按钮，原来要右键的菜单由画布的长按代替，所以手指也能用。横拿的手机高度太矮，放不下桌面壳的输入框和面板，因此归手机壳。

  `whole` 的壳（手机）占满屏幕：App 在 `.app` 上标 `data-whole`，左侧栏不显示，壳自己的返回按钮回到首页。`index.html` 带 `viewport`（`width=device-width, initial-scale=1, maximum-scale=1, viewport-fit=cover, interactive-widget=resizes-content`），手机才按真实宽度排版，页面本身不缩放（画布自己缩放）。iOS 会在字号小于 16px 的输入框获得焦点时放大页面且不缩回，刷新后还保留，所以 `base.css` 在 `pointer: coarse` 时把所有输入框定为至少 16px；`viewport.ts` 的 `followViewport` 把 `.app` 放进可视视口（`--seen-top`/`--seen-height`，键盘弹出时输入框留在键盘上方，键盘收起后把被 iOS 卷走的页面卷回去），并拦下 Safari 自己的 `gesturestart`/`gesturechange`，双指不会放大整页。`Tooltips` 只认鼠标：手指按下时显示新内容会让 iOS 把这一下当成悬停、吞掉随后的点击。凡是从按钮弹出的菜单都经 `popover.ts` 的 `useDismiss`（按外面或 Esc 关闭），它调用 `ui/place.ts` 的 `useInView`：菜单按自己的 CSS 摆好后量一次，超出可视视口就换到空间大的一侧、沿边滑回、太高就在里面滚动（用 `translate` 和 `max-height` 修正，不管包含块是谁），可视视口变化时重量。
- **手机壳** `phone/`：围绕“看和说”设计，不是桌面版缩小，桌面的界面状态和交互习惯都没有搬过来：
  - **页面**：`WorkPage.tsx` 管页面怎么用：选区、打开的底部面板（`SheetKind`）、详情页、收起的回复、就地改字、换图的素材对话框。只读运行开始结束、换场景时才变的东西。
  - **部件**：`parts.tsx` 里的部件各读各的那一片。
    - `TopBar`：返回首页、标题（打开 `ScenesSheet`：改名和场景列表）、撤销、画室与版本（按钮角上盖着当前版本的印）、导出分享，按钮都是 44px。画室和版本是同一个底部面板的两个标签（`StudioSheet`/`VersionsSheet` 头部的 `HistoryTabs`），所以回复收起后、重新打开作品后，画室总能从顶栏打开。
    - `PhoneCanvas`：铺满屏幕，`editing` 始终为 false；`controls={false}` 不显示缩放按钮（靠双指）；`resizable={false}` 不显示缩放手柄（调尺寸属于精细排版）。`fill={FILL}`（2）：竖拿手机时，宽的图整幅放下字太小，自动视角最多放大到整幅的两倍去铺满屏幕，从图的左上（阅读开始处）摆起；`Whole` 在视图没有放下整幅图时（`Canvas.showsWhole`）浮在底部右上方，点它 `fit(…, "whole")` 看全图。
    - `Notes`：预览、错误、回退可撤销、挂起与未保存修改，按钮横排可换行。
    - 手机输入框最多长到可视高度的四分之一（`phone.module.css` 末尾），再多就在框里滚动，发送按钮始终在屏幕上。
    - `Actions`：选中一个模块时，在输入框上方出现改字（模块有画出的字时）、换图（模块数据引用了图片素材时，`picturesIn`）、说说怎么改、删除；名字和取消选择在上面一行，名字再长也不会把取消选择挤出屏幕。
    - `WorkStatus`/`WorkComposer`：作者作画时输入框收起成进度条。画室不自动打开，因为手机上画布才是要看的；点进度行从底部拉出 `StudioSheet`。
    - `VersionsSheet`：点一个版本就收起面板、在画布上原地预览，预览条里可回到这一版。

### 首页与示范作品

`/` 是 `home/Landing.tsx`，分两段：第一屏（`Hero`）只放提问（标题、一句说明、输入框、示例问题和空白画布），`min-height: 100cqh` 撑满滚动容器（`.l-page` 设了 `container-type: size`）；其余都在 `.l-intro` 里，是叠在桌面上的一张纸（`overflow: clip`，让顶上的方格纸随圆角裁齐，又不妨碍吸顶），第一屏底部的按钮滚到它。纸上依次是故事段（`Story`）、滚动的“大家都在问”（`Ticker`）、画好以后能做的六件事（`Features`）、常见问题和页脚。首页的字是写给用户看的：短、口语、不讲实现（不提画法代码、截图、作者这些）。空白画布挪到了 `/new`（`routes.ts` 的 `new` 页，App 对它的处理和原来的首页相同：`blankSession`、可拖入文件、访客不弹登录）。首页里的输入框是 `Composer` 的 `home` 形态，发送仍走 `asking.send`：没有打开的作品时先建作品再发出。

首页上的图都是真正的作品，用作品页同一个 `Canvas` 绘制（`home/LiveWork.tsx`）：靠近屏幕时才创建；滚轮交给页面滚动，只有捏合或按住 Ctrl 才缩放画面；`touch-action: pan-y` 让手指上下滑动时页面照常滚动；指向场景的模块在原地切换场景，指向详情的打开详情页；作品对象或场景变化时重建画布，待新画布就绪后显示，因此切换语言会重新绘制，切换章节或子场景会按新内容取景；`insets` 给纸边留白（进了子场景时给返回条留出位置）。这些作品的源码在 `apps/showcase/works/*.ts`，按作者的方式写：一份简报加一串 `WorkEdit`（每一项是一版）；作品自己的画法代码放在 `apps/showcase/drawings/*.js`，一个画法一个文件（和作者写进 `source` 的一样，是一段以 `return` 结尾的函数体），由 `kit.ts` 的 `code(name)` 读进去，这样它们读起来就是代码，而不是模板字符串里的字符串。故事段是一条线索上的十件作品：同一座灯塔，从一幅画问到造它的一家人（`night`、`styles`、`inside`、`lens`、`rhythm`、`range`、`coast`、`navigate`、`history`、`family`），前后呼应——转台闪光的灯质出现在夜航的海图上，地图上每个建造者的颜色就是家谱里那人小像的圈色。它们的动画都按 `performance.now()` 计时，而不是 `api.animate` 给的秒数，所以脚本 `api.set` 重画一个模块时节奏不会从头开始，海面倒影和灯塔光束这类分在两个模块里的东西也能对上同一个时钟；需要“没人碰时自己演示”的（画风、剖面、透镜、地图、时间线、家谱）在画法里自带一个计时器，一被点就停，计时器用 `api.cleanup` 收掉。地图那件的灯塔层和下面的 `geomap` 模块同位同大，按 `geomap` 相同的等距圆柱投影（经度乘中纬度余弦、再撑满模块的宽高比）把经纬度换成坐标。`apps/showcase/build.ts` 把它们发给一台正在运行的 DrawY（`POST /api/works` 再逐版 `POST /api/works/:id/edits`，由服务端像对待作者的 `write_work` 一样收进素材），把每版取回的作品连同简报存成 `apps/web/src/home/showcase/<id>.<zh|en>.json`（同一作品各版共用的素材只存一份）；`home/showcase.ts` 按需动态加载。改了示范作品后：

```sh
DRAWY_URL=http://127.0.0.1:8080 DRAWY_ADMIN_USER=… DRAWY_ADMIN_PASS=… pnpm exec tsx apps/showcase/build.ts [id…]
```

首页的动效都跟着内容走，不为装饰而动，`prefers-reduced-motion` 时全部换成直接切换（`home/motion.ts`）：
- 第一屏输入框空着时，`useCycledTyping` 逐字打出故事各章的 `ask`（也就是下面那些作品的提问），打完停一会儿、清空、换下一句；轮到 `reference` 一例且输入框空闲时，在输入框左上角（真实附件区域的位置）显示同一张灯塔参考图缩略图；点进输入框、按键或添加实际附件后停下并收起缩略图、换回普通的占位提示。只有聚焦不算，因为输入框可能自己拿到焦点。
- 故事段的第一页是 `reference` 画风参考页（`ReferenceSheet`）：左侧展示静态灯塔剖面参考图（`/style-reference-lighthouse.webp`），右侧是 DrawY 参考它完成的老式唱片机导出（`record-player.json`，经 `loadShowcase` 延迟读取并用 `LiveWork` 实时渲染，可点开皮带传动详情），页眉列出示例提示词、页脚列出沿用的画法图例；进入视野且该页激活后，朱红箭头先描边画出，唱片机各模块依次显影，减少动态时直接显示成稿。
- 故事段的其余十件作品在它进入视口 800px 内时一次全部加载（合计约 270KB 未压缩），长距离跳转时不用中途等。作品都按 1280×750 左右的横幅来画，所以速写本是横放的（`.l-story-boards` 的 `aspect-ratio`），故事段两栏（约 3:9，最宽 1600px）让右边的速写本占大头。故事段的底是浅色方格纸（`--l-band` 上两层蓝铅笔方格），不用深色。
- 故事段（`Story`）有两块叠放的纸（`.l-story-slot`），是一本顶上用线圈装订的速写本（`.l-story-boards::before` 画线圈，`--l-stack` 画出底下几层纸边），章节 `k` 总在第 `k % 2` 张上：`from` 是完整显示的一章，另一张垫在下面放着下一章。滚动时在 rAF 里量各章到阅读线（桌面是视口中线，手机是 80% 处）的距离，下一章顶边越过阅读线前后各半个 `span`（视口高的 45%，最多 420px）内是翻页区，进度 `p` 再做一次 smoothstep。翻页是捏住右下角往上掀（`motion.ts` 的 `turnedUp`）：角从原位沿一条向左鼓的弧被带到顶边之外，折线是角的原位与现位的垂直平分线；上面那张用 `clip-path` 只留下折线这一侧（`keep`），掀起的部分由 `.l-story-curl` 里一张纸背按折线镜像（`matrix` 反射）铺回来，纸背上的 `--curl` 渐变画出折痕处的高光和往角尖渐暗；下面那张的 `.l-story-shade` 沿折线落一道随掀起变宽的阴影，并整体由暗变亮。纸背的盒子 `overflow: hidden`，越过顶边就看不见了。这些直接写在 style 上，不经 React；React 只在 `from`、`at`（过半的那一章）变化时重绘，所以换下去的那张是在看不见时才换上新作品。看不见的一张 `inert`，也不接收指针。同一帧里还给每章写 `--light`：它是这一章“正在被读”的程度，等于它自己的翻入进度乘以下一章翻入进度的余量，所以和翻页严格同步；CSS 让小标签、标题、正文按 `--light` 依次错开一点亮起（退出时反过来），用不透明度加 `brightness` 表现明暗，减少动态时只有全亮和全暗。还写 `--sp`（圆点下的线点亮到哪里）和 `--drift`（方格横线的偏移，让它以页面 0.8 倍的速度移动）。
- 速写本下的 `Pager` 每章一个圆点，依章节数量等分；窄屏画板在整段章节滚动时吸顶。圆点和章节都能点，`jump` 把那一章滚到交接区之后。
- 首页的作品都放在 `Sheet` 里：一张纸（`--l-paper`），上面用 `mix-blend-mode: multiply` 叠着纸纹（`--l-grain`，细颗粒）、纤维（`--l-fibre`）和边缘的微暗，画布自带的点阵在这里关掉；纸上只有作品，进了子场景才在顶上出现返回上一层的小纸条（`.l-sheet-back`），`LiveWork` 的 `insets` 随之在顶上多留一点。
- 页脚“能画的图”列出各章的 `kind`，按下时与圆点共用同一跳转位置，使对应章节（`#l-chapter-<id>`）成为当前章。
- 常见问题用 `::details-content` 加 `interpolate-size: allow-keywords` 过渡高度，不支持的浏览器照常直接展开。

示范作品里的图片引用 `/materials/files/…`，所以页面需要素材服务在主程序后面。首页的样式在 `home/landing.module.css`，类名都以 `l-` 开头，`home/cx.ts` 还会解析到 app 的样式表（共享输入框和画布上的目标标记）；由别的组件画出来的元素（输入框、印、品牌）用结构选择器定位，不在本表里重定义它们的类名。

## 手动编辑如何流动

原则：手动编辑的能力等于作者 `write_work` 的能力，不多也不少。每个手动操作都算出一份只含变化的 `WorkEdit`，经 `POST /api/works/:id/edits`（`{baseRevision, edit}`）交给 `writeWork`，和作者的写入是同一种写法、同一套校验，落到作品上是同一个 `layOn`。所以协议里没有的东西（旋转、透明度、锁定之类）手动编辑也不能有；要加这类能力，得先改协议，让作者同时拥有。反过来，作者能写的（模块的名字、位置、编组、跳转目标和数据，连线及其两端，场景及其脚本，详情，作品画法的代码、默认值与参数，共享样式，取用素材），手动编辑都有入口。`set_brief`、`generate_images` 和 `view_canvas` 是作者的创作工具，不是对作品的修改，不进编辑器。

用户在绘图页点铅笔（或双击画上的文字）进入编辑模式，画布变成一块“图板”（概念见下文“界面像绘图工具”一条里的“上图板”），右侧面板换成 `apps/web/src/Editor.tsx`。图板上的东西各在一个文件里：
- **工具盘** `EditTray.tsx` 的 `EditTray`，竖排在画布左缘，只有九个按钮：选择 V、平移 H，一个形状按钮（显示上次拿的形状，角上小三角展开全部七种并标出 R/O/D），文字 T、连线 L、箭头 A、画笔 P、橡皮 E、画法库，以及“插入”（图片、导入）。形状不是新的图种，只是库画法 `node`/`callout` 带上相应的 `shape`（`desktop/editing.ts` 的 `stamps`）；拿着形状或文字工具在画布上拖出大小或点一下即放下（画布的 `draw` 工具回调 `place(at, box?)`，`useEditing` 的 `place` 按手里的工具决定放什么），放下后工具回到选择、新元素直接进入就地改字（`retypeNew`）。画法库是一张浮层（`Shelf`）：按用途分组、可搜索，每个画法用 `Library.tsx` 的 `DrawingLook` 现画（滚动到才画，`Seen`），点一下放到视图中央，或拖到画布上（`DRAWING_TYPE`，桌面壳在 `stage` 的 `onDrop` 里接，图片文件也在这里接）。浏览和搜索得到的画法不带代码和示例，`ops.drawing` 放之前先按 ID 取完整画法，新模块带着它的示例数据。库里的画法在没有数据、列表清空或只有一条空项时也要画得出来（只少画内容，不报错），运行时测试逐个检查；只有没指定图片的图片画法会报错，作者靠它知道漏了图片 ID。
- **手绘与导入**：画笔、箭头和橡皮是画布自己的工具（见下文的手势）。画笔画完仍拿在手里，箭头画完回到选择（经 `useEditing` 的 `ink`；箭头连上两个模块时走 `connect`，同样回到选择）。导入在 `Bring.tsx` 的 `BringDialog`：粘贴代码或打开 `.excalidraw`/`.mmd`/`.md` 文件，`interchange.ts` 的 `incoming` 认出是什么、`clipOf` 变成 `Clip`，交给会话的 `bring`；对话框的开关在 `useEditing` 的 `bringing`，所以工具盘和空白画布都能打开它。画布上粘贴的文字（`onPaste`）和拖进来的文件（`WorkPage` 的 `onDrop`，`importable`）认出是 Mermaid 或 Excalidraw 时走 `bringIn`。场景还空着、没有运行时，`SceneView` 在“这里还空着”下面放壳给的 `start`：桌面壳不在编辑时是“开始画”（进入编辑，手里是选择工具）和“导入”，编辑时是一行提示。
- **选区下方的条** `EditBar.tsx` 的 `SelectionBar`：只有“外观”快捷控件和“更多”（在原处打开右键菜单），复制、编组、删除、说说怎么改在面板顶上、右键菜单和快捷键里，条尽量少挡住图。快捷控件来自 `editing/fields.ts`：`sharedFields` 取所有选中部件共有的选项、颜色、数字和开关（同名同类型，选项相同），`quickFields` 按 `QUICK` 的顺序（`shape`、`tone`、`color`、`fillStyle`、`size`、`route`、`head`、`dashed`、`both`、`align`、`weight`）挑前五个，所以库画法和声明了同名参数的作品画法都自动得到控件，新画法不用改这里；选中的模块和连线一起算共有选项，改动经 `ops.restyle` 一次写到所有选中的部件上。条经 `Canvas.watch` 跟着视角和选区移动、按 `selectionRect` 定位：放在选区下方、让开尺寸标注和边上的加号，下方到输入框（`[data-dock]`）或画布底边放不下时放到上方；拖动时（`Canvas.dragging`）、右键菜单打开、就地改字或手里不是选择工具时隐藏；从条上弹出的小面板朝离开选区的方向开（`data-low`/`data-under`）。
- **右键菜单** `EditMenu.tsx`：带图标；选中模块时多了拷贝外观/粘贴外观（`lookOf`/`pasteLook`，只带选项、颜色、数字和开关，不带文字和图片；同一作品的同一画法全盘照搬，跨作品或不同画法只取同名同类的）、“选中同类元素”（同画法的模块和连线）、“选中整组”（选的是一个组的一部分时，`ops.selectGroup`）和“选中框住的元素”（选的模块框住别的模块时，`ops.selectInside`，按 `carried` 算）；只选了连线时是调转、外观、选中同类和删除。
- **标尺与视图** `EditView.tsx`：`Rulers` 是画在两个 `<canvas>` 上的上、左标尺（场景单位，选区在标尺上投出蓝色区段，指针处一条细线），`ViewControls` 是画布右下角的视图控件（不编辑时也在）：缩小、显示比例、放大、看全图；点比例打开菜单（100%/50%/200%、看全图、看选中的部分），编辑时菜单里还有图板设置（`useBoard`，记在 `drawy.edit.board`：标尺（默认关，给画布让地方）、对齐相邻元素、吸附到方格 `GRID`=20）和快捷键表（`Editor.tsx` 的 `ShortcutSheet`，按 `?` 也打开）。舞台窄于 1040px 时只留比例和看全图（`data-compact`）。
- 编辑时输入框收起（`stage` 的 `data-quiet`，CSS 只藏 `.composer-wrap`，上面的提示条照旧）：“说说怎么改”（选区下方的条、面板、右键菜单，空白处的“说说整张图怎么改”）和改不了时交给作者的修改都走 `draft.hand`，请求的 `asked` 一变，桌面壳订阅到就把 `describing` 置真，输入框出现并取得焦点；焦点离开 `[data-dock]` 时放下 `describing`，但里面有字或附件、作者在画或在等回答时输入框一直留着；离开编辑也放下。这期间 `[data-dock]` 高度变化不再触发 `refit`，自动视角也不会在手动编辑时自己移动。
- 属性面板可以收起（`tucked`，面板标题右侧的按钮；收起后画布右上角有“属性”按钮打开），窗口窄到面板会盖住画布（`roomy()` 为假）时进入编辑默认收起，画布上的工具盘、条和菜单足以完成常用操作。

面板分“属性”和“图层”两页：属性页选中模块时（可以同时选着连线），顶部吸附着名称（多选时是“已选 N 个元素”，连线也算一个）、画法名和一排图标操作（复制、编组/解组、置顶、置底、说说怎么改、删除），下面依次是位置与大小（X/Y/宽/高，可锁比例，多选按整体换算；改 X/Y 时选区框住的模块（`carried`）一起平移；字母可左右拖动调整，拖动中经 `Canvas.reshape` 预览）、对齐分布与等宽等高（`matchSize`，以第一个选中的为准）、多选（或模块连同连线）时的“外观”（`Shared`：选中的模块和连线的 `sharedFields` 全部控件，各不相同的值显示为未选）、内容（`EditControls.tsx` 的 `Fields` 加 `DataEditor`）、点击后（不跳转、某个场景或详情，或当场新建子场景/详情）、连线（每条一行，点一行即 `canvas.select([], [id])` 选中它，行内可调转、删除）和折叠的“画法与代码”（`EditCode.tsx`：换画法、库画法复制为作品画法、共用画法只改这一个、画法代码与参数、整条模块记录的 JSON）；只选了几条连线时是 `Links`：“已选 N 条连线”、一起调转、选中它们两端的模块、说说怎么改、删除，下面是它们共有的外观；只选了一条连线时是 `LinkPanel`：两端各一个模块下拉框和边的分段选择（换模块时取朝向另一端的边）、调转、选中两端模块、内容（同样的 `Fields`/`DataEditor`）和连线画法（场景里连线用过的画法和库里的 `arrow`，从素材库选的必须是 `use: "link"`）；没选中时是场景（标题、子场景、交互脚本、删除场景）、作品外观（所有样式 token，加套用库风格的配色）和详情页（`EditWork.tsx`）；添加在工具盘里，快捷键在单独的表里。选中的东西变了面板回到顶部。图层页按上下层列出模块，可点选、Shift 加选、双击改名、拖动改层级，下面列出场景的连线，点选即选中，Shift 加选（和模块一起）。面板控件不按版本重建（`Fields`、`DataEditor` 只按部件 ID 作 key），保存不会打断正在输入的下一项：文字框、滑块在没被使用时才跟上作品里的新值，数据编辑器的一项被别处改了（撤销、作者）才从新值重来，自己保存回来的不算。选项超过五个用下拉框，少的并排、放不下换行。代码类输入（`Code`）在保存前用 `syntaxError` 检查语法，记录类输入用 `contracts` 的 schema 校验。

画布（`modules/canvas`）在 `Canvas.setEditing(true)` 时于捕获阶段接住点击，画法里的按钮和模块的跳转目标都不响应。编辑模式下按下的位置由 `pick` 决定：先是在那里真正画了东西的模块，再是经过附近（屏幕 10px 内）的连线，最后是框住这一点的最小模块；连线画在底图之上，所以按在底图上、连线附近的点选中连线（`beneath`），铺在底下的大模块不会挡住它上面的连线；框住别的模块的分区（`holds`）也一样，分区里的连线照样点得中。连线的命中按它画出来的样子算：`traceOf` 把连线影子 DOM 里每个 SVG 几何元素沿路径取样、文字取外框，换成场景坐标缓存到连线重画为止，HTML 画的连线退回两端间的直线。选区是模块和连线两份列表（`select(ids, links)`，读回用 `selected`/`selectedLinks`，变化经 `options.select(selection, links)` 告诉前端；`selectAll` 编辑时连线也选上），悬停的连线和选中的每条连线都描一层半透明的强调色；只选了一条连线（`onlyLink`）时两端出现圆点（`data-link-end`），拖到某个模块上调用 `options.reconnect`（不能接到另一端所在的模块），拖动时虚线吸到目标边的中点上并画一个圈。其余手势按主流绘图软件来：
  - 单击模块选中它的整组（`unitOf`）；选区已经在这个组里面（选的是组的一部分）时只选这一个，按住 ⌘/Ctrl（`deep`）直接选这一个；在已选的多个里按下不拖就松手，收成这一个（`narrow`：选区正好是一整组时收成按下的模块，即“再点一下进组”），所以组里的单个模块可以直接拖动。不在编辑时单击只选那一个模块（好打开它的目标），拖动时才带上整组。
  - Shift 单击加选或取消（编组的按整组，进了组的按单个），连线一样，模块和连线可以一起选；连线没法拖，单击连线只选它。
  - 用鼠标在纸上拖出框（`marquee`）选中完全在框里的模块和连线（连线按 `traceOf` 取样的点和字框都在框里算），按住 Alt 改成碰到即选，编组按整组算（全在框里才选，Alt 时碰到一个就整组）；整个框都落在里面的模块（框是在它上面拖出来的）不算。按下时按住 Shift 的框加在原来的选区上。在没选中的分区（`holds`：有别的模块画在它上面且整个落在它框里，`editing` 的 `carried`）上拖动也是框选，不拖就松手才选中分区（`on`）；手指在分区上照常选中拖动。
  - 拖动选中的模块时，它们框住的模块（`carried`，按场景的层序算，只算画在上面的、比它小的）一起走，方向键（`nudge`）也一样；Shift 锁定水平或垂直；按住 Alt 拖动是拖出一份复制品（连同框住的，原件留在原处并画出虚线框，松手时调用 `options.duplicate(ids, by)`，不调用 `commit`）；选的是组的一部分时，组的范围画一个虚线框（`groupBox`）。
  - 拖动和自由缩放时边缘与中线吸附到其他模块（`editing` 的 `snap`，屏幕上 6px 内，红色参考线，按住 ⌘/Ctrl 不吸附），移动时还吸附到等距的位置（`snap` 的 `spaced`：夹在同一行或同一列的两个邻居正中，或与最近的邻居保持它和下一个邻居的间距；对齐与等距都够近时取更近的，一样近取对齐），等距的间隙用红色尺寸线标出数值（`Gap`）；开了“吸附到方格”时，没对上邻居的那个方向落到方格线上（`setSnap` 的 `grid`，拖出的新形状和自由缩放也是）；选区外框有 8 个手柄（`resized`：Shift 保持比例、Alt 从中心），多选时按 `scaled` 整体缩放；手柄和圆点是比画出来的标记大得多的透明按钮，好按。编辑时选区按工程图的方式标注尺寸（`paintDims`）：宽在下方、高在右侧，各是一条两端带 45° 短斜线的蓝色尺寸线，数字压在线上（场景单位），拖动、缩放和拖出新形状时跟着变；移动时左上角另有一枚写着 X、Y 的小签。单选时，鼠标靠近哪一边（`nearSide`，44px 内取最近的），那边外侧就出现一个带加号的圆点，那一侧的尺寸数字让给它：点一下调用 `options.extend(from)`，在那一侧延伸出一个相连的同类元素；拖到另一个模块上调用 `options.connect`，由 `facing` 定终点的边，同样标出目标边；拖到空白处松手调用 `options.extend(from, at)`，在那里新建。连线工具（`setTool("link")`）从按下的模块拖到松手的模块，`connect` 的两端不带边，于是连线两端不写 `at`、随模块移动自动换边；它拖到空白处同样是 `extend`。画笔（`pen`）把指针走过的点（含合并事件 `getCoalescedEvents`，相隔不到一个屏幕像素的不记）记在 `ink` 手势里，箭头（`arrow`）只记起点和当前点（Shift 锁到每 15°），画的时候在一层屏幕坐标的 SVG 上预览，松手时调用 `options.ink(points, { kind })`；箭头从一个模块（按真正画了东西的地方算）画到另一个模块时改为调用 `options.connect`。橡皮（`erase`）沿指针路径每 4 个屏幕像素取一点（`rub`），碰到的模块（连同它的编组）或连线淡到 0.2（和 `pick` 一样，背景上画着连线的地方擦的是连线），松手调用 `options.erase(ids)`，取消时恢复。手指不会悬停，所以粗指针设备上四个圆点一直都在，尺寸标注只在缩放时出现；右键先让选区跟上（`follow`：落在已选的东西上就不变，否则换成它，模块按整组）再调用 `options.menu`（前端的 `EditMenu`）；按住空格、中键或平移工具拖动平移，绘制工具（`draw`：按下即放、拖动拖出一个框，Shift 为正方）和双击空白处调用 `options.place(at, box?)`；双击按坐标找到模块影子 DOM 里的文字或图片，交给 `options.point`，双击连线上的字也交给它（`link: true`，`moduleId` 是连线 ID），连线上还没有字时交出空的 `text`，前端把输入的字写进它画法的第一个文字参数；`wordsIn` 给出模块画出的第一段文字，供 Enter 就地改字。拖动和缩放时模块先由 `SceneRenderer.position` 立即放到新位置（缩放先拉伸外框），需要重画的部分（改了尺寸的模块、连到它们的连线）每帧最多画一次、总用最新的位置（`drag`），松手时提交手势记下的最终位置；`SceneRenderer.move` 只重画连到被移动模块的连线。编辑时纸面换成方格纸（每 20 单位一条细线、每 100 单位一条粗线，太密时步长乘 5），都是 `paint` 里设的行内背景。`reveal(ids)` 在刚做出的东西不在视野里时把视角平移到刚好看全（会话的 `made` 在选中新模块后调用，`View.reveal` 是可选的），`zoomTo`、`frameSelection` 供视图控件和快捷键使用，`insets` 可以带 `left`/`right`（编辑时给工具盘和标尺让出位置）。

触屏手势是画布自己的能力，所有壳都有。画布带 `touch-action: none`，所以浏览器不会拿手指去滚动或缩放页面。指针事件按 `pointerType` 区分手指和鼠标：
- 每根手指的位置记在 `touches` 里；第二根手指落下（落在画法里的按钮上也算）时，第一根手指开始的手势作废（拖动中的模块回到原位），换成 `pinch`：两指的中点带着视角走，两指间距按比例缩放（`zoom`）。抬起一根手指就结束，剩下那根不再起作用。单指手势只认开始它的那根手指（`gesture.pointer`）。
- 单指在模块上的效果和鼠标一样（选中、拖动选中的或编辑中的模块）；在纸上总是平移视图，编辑时也一样（框选留给鼠标）。
- 手指不动按住 `HOLD_MS`（500ms）是长按：先让选区跟上手指按下时下面的东西（按下时就找好，因为选中会让手机的操作条出现、视图在手指下重新取景），再调用 `options.hold`；没有提供 `hold` 时，编辑中就调用 `options.menu`，相当于右键。之后浏览器自己发出的 `contextmenu` 被拦下。
- 两次点按相隔 `DOUBLE_TAP_MS` 以内、距离 `DOUBLE_TAP_PX` 以内，算双击，走 `dblclick` 的逻辑；随后浏览器补发的 `dblclick` 不再处理（`doubledJustNow`）。手指双击到模块上没有字的地方时，改它画出的第一段字（`wordsIn`），因为指尖盖住的不止一个点。
- 手指移动 `FINGER_STILL`（8px）以内仍算按住，连线命中范围是 `FINGER_SLOP`（24px）。
- 设备有粗指针（`any-pointer: coarse`）时，缩放手柄、连线圆点和连线端点的可按范围都是 44px。
- `resizable: false` 去掉缩放手柄，选中的模块仍可拖动。

桌面壳 `useEditing` 的 `ops`（会话的 `ops` 绑到选区，加上 `add`、`shape`、`extend`、`restyle`、`matchSize`、`copyLook`/`pasteLook`、`selectSame`、`selectGroup`、`selectInside`）是作用于选区的操作集合，选区是选中的模块加上选中的连线（`parts`）：右键菜单、工具盘、浮动操作条、面板的操作按钮和键盘都调用它；面板里不经选区的修改（某个字段、某条列出的连线、场景、详情、样式 token）把 `modules/editing` 的纯函数交给会话的 `change`，同样排进 `edits`、失败经 `feedback` 报出；`remove`、`restyle`、`pasteLook` 作用于选中的模块和连线，`reverse` 一次调转所有选中的连线，`reconnect` 作用于一条连线；对齐、编组、层级、复制只管模块（复制带上选中模块之间的连线）。会话的 `ink` 用 `inked` 做出手绘线部件，以 `paste`（偏移 0）放在画的地方，线宽取约两个屏幕像素；`bring` 把导入的 `Clip` 放在视图中央，压住已有模块时放到场景内容右边 80 单位处，作品自带画法占用了库画法 ID 时，像加库画法一样带上库画法的副本（`libraries`）；空白画布上它们和其他添加一样先 `materialize`。剪贴板走系统的 `copy`/`cut`/`paste` 事件：拷贝时写入 `application/x-drawy+json` 的 `Clip`（`editing` 的 `copy`：模块、它们之间的连线、用到的作品画法和库画法，以及素材 ID），同时存进 `Clipboard`，所以能粘贴到别的场景、作品或标签页；粘贴回原处时每次错开一步，粘到别处时放在视图中央；剪贴板里是图片就上传后作为图片模块放进来，是文字就作为文字模块。快捷键：工具 V/H/R/O/D/T/L（只选了连线时 R 是调转它们）；⌘A 全选（模块和连线）、Tab 轮选、⌘D 复制、⌥⌘C/⌥⌘V 拷贝/粘贴外观、⌘G/⇧⌘G 编组/解组、⌘]/⌘[ 置顶/置底（加 Alt 为一层）、Alt+A/D/W/S/H/V 对齐、Alt+Shift+H/V 等距分布、方向键微调、Delete 删除选中的模块和连线（只选了连线时 ⌘X 也是）、Enter 或 F2 就地改选中模块的字；视图 ⌘+/⌘−、⌘0（100%）、⇧1（看全图）、⇧2（看选中的部分）、`?`（快捷键表）；Esc 先放下手里的工具，再取消选择。发给作者的请求在选中的模块之后，每条选中的连线附一行 `Selected link: <id> (<起点模块> → <终点模块>)`（`aboutOf`，`Focus.links`）。

每个操作都是 `modules/editing` 里的纯函数（按职责分文件：`fields`、`parts`、`layout`、`links`、`words`、`clipboard`、`work`、`changes`），从当前作品算出一份 `WorkEdit`（`apply.ts` 的 `applied` 把它叠到作品上，和 `writeWork` 用的是同一个 `layOn`；两步合成一步用 `composed`）：`setData`、`moveParts`、`rename`、`removeParts`（连带删掉相关连线和检查）、`duplicate`（复制品自成一组，并复制它们之间的连线；偏移是一个步长或 Alt 拖出的 `{x, y}`）、`restyle`（同一组值写到多个模块或连线上）、`pasteLook`、`matchSize`、`arrange`（置顶、置底、上移或下移一层：越过下一个与它重叠的模块）、`restack`、`group`/`ungroup`、`setTarget`、`useDrawing`、`setModule`、`add`（文字、图片或库画法，库画法带它的示例数据和尺寸；给了 `box` 就按拖出的框放，没给名字的模块按它的字命名）、`align`/`distribute`、`connect`（连到两个模块的边上，不给边的一端不写 `at`，不动模块；新连线沿用场景里最近一条连线的画法和数据，`linkLook`，没有时用库里的 `arrow`）、`extend`（从一个模块的某一边长出一个同画法、同外观的新模块并连上：主文字换成占位词、其余文字不带；没给落点时放在那一边之外一个 `gap`，被占了就沿那条边错开，直到不压着别的模块）、`reattach`（换一端所在的边，不给边就回到自动跟随，给了模块 ID 就换到那个模块上，不能接到另一端所在的模块）/`reverse`、`replace`（给的是连线 ID 时只改连线数据里的字或图片）、`paste`（新 ID；同 ID 而代码不同的作品画法换新 ID；剪贴板也带着用到的库画法，目标作品有同 ID 的自带画法时，库画法连同默认值以新 ID 作为作品画法放进去；目标作品没有的跳转目标置空）、`setStyle`/`setStyles`、`addScene`/`renameScene`/`removeScene`（连同下面的子场景，指向它们的模块不再跳转）、`setDetail`/`removeDetail`、`setInteraction`、`setDrawing`、`fork`。`replace` 先在模块数据里找要改的字或图片 ID（改的若是某一项的 `name`，数据里所有与它完全相同的字串一起改，比如地图的路线、区域、`highlights` 按地点名引用它，只改一处路线就会丢掉这个点）；找不到时，如果它在画法代码里只出现一次，就按所在位置转义后替换，画法被别的模块共用时先为这个模块复制一份，替换后代码必须还能解析；都不行就返回 `null`，前端把修改要求写进输入框交给作者。`fieldsOf` 决定面板显示哪些普通控件：先是画法 `params` 声明的（名字可写可不写，没写时来自 `i18n.tsx` 的 `edit.params`），再是画法 `defaults` 和数据里其余的文字、颜色、数字和开关；小写的英文单词当作代码里的状态，不显示。其余的数据（列表、记录、状态词，`restOf`）进数据编辑器：列表可增删、上下移动（新增一项是复制最后一项），超过 12 项的先折叠成“展开 N 项”（手绘线的点、长表格），记录可增删字段。

会话的 `edits` 把这些修改排成队，依次从上一次结果出发，服务端把原因记为 `{ kind: "edit" }`（未保存的修改，见上文 `historyOf`），作者运行期间返回 409。修改不等服务器回应就显示：`commit` 先在“排队修改都完成后的作品”（`drafted`）上算一次，`showable` 时用 `applied` 得到草稿交给画布和面板（`SceneView` 的 `version` 区分同一版本号的不同显示），队列清空时换回服务器的作品，任何一次失败都丢掉草稿；服务器存好的修改交给 `Revisions.edited`，它的那条修订原因已知，直接记进修订列表，未保存数随之加一，不等 `/revisions` 回来；自己的修改在路上时，服务器推给各页面的同一份作品先由 `heard` 放着，回应带着它回来后丢掉，回应没来才采用（否则作品修订号先变、列表还没跟上时未保存数读作 0，未保存提示条每改一次就消失再出现）；要取用作品还没有的素材的修改（换图、新库画法，包括模块或新连线用到作品还没取过的库画法，比如空白画布上的第一个文字）等服务器取到素材再显示（`showable`）。所以 `make` 可能被调用两次（草稿一次、提交一次），里面不要放只能执行一次的副作用。用户自己造成的版本（手动编辑、撤销、回退）在画布上安静替换，不播放起稿动画：`SceneView` 问会话的 `quiet`，再调用 `Canvas.update(…, quiet)`； `SceneRenderer.patchable`（同一场景、样式和交互脚本没变、两边都有的素材没变）时调用 `patch` 原地更新，只重画画法、数据或尺寸变了的模块，移动的只改位置，删掉的拿走，新的画上，按新顺序调整层级，连线全部重画；其他情况才另起一个渲染器整体替换。下次作者运行时，`changesBetween` 列出的不只是场景里模块的增删改移和层级，还有场景本身的标题、父场景、脚本和交互检查清单，整个新增或删除的场景，以及画法、详情的增删改，提示词要求作者保留。

## 结构化编辑的设计

这一节记下让“用库画法搭结构图”“随手画”“接着改 AI 画的图”都顺手的几项设计，以及取舍。实现分阶段落地，每项完成后在上面对应的章节里写实际做法。

**数据 schema（`fieldSchema`）取代参数声明。** 画法用 schema 声明它读取的数据：`text`、`number`（`min`/`max`/`step`/`unit`）、`color`（可写主题 token）、`boolean`、`picture`、`effect`、`choice`（`options` 每项带 `{zh,en}` 标签和可选图标名）、`id`、`ref`（`to` 指向同一画法里某个列表）、`list`（`item`、`title` 标题字段、`new` 新条目默认值、`min`、`cascade`、`next`）、`record`（`fields`）、`tree`（`children`）和 `geo`。每个字段有 `label: {zh,en}`（作品自带画法可省，退回 `i18n.tsx` 的 `edit.params`，再退回把键名转成可读文字），`quick: true` 的进选区工具条。库里的 `Param` 是同一个 schema 加上给作者看的 `description` 和 `default`。schema 定义在 `materials/fields.ts`，`contracts` 原样导出：素材服务的镜像只带 `materials/`，素材包校验和作品协议必须共用同一份定义，放在 `modules/contracts` 里素材包就够不着它。`effect` 不在任务列出的类型里，但 26 个库画法读效果 ID，它是一种素材引用，和 `picture` 并列。

- 列表里的记录一律带稳定的 `id`，引用存 `id`；纯文字或数字的列表（雷达图的轴名、循环的阶段名）按位置读，不带 `id`，因为它们没有可引用的身份。作者写数据时可以省略 `id`，服务端按内容生成确定性的 `id`（标题的拉丁字母缩写，否则内容的短哈希，重名加序号）；记录列表里写一个字符串表示只有标题的记录；引用可以写名字，服务端按 `title` 字段归一成 `id`。名字有歧义或找不到时，和其他问题一起按记录和字段报出。
- `WorkEdit` 的数据补丁可以按 `id` 定位列表条目：`{"messages":{"#m3":{"label":"…"}}}` 改那一项，值为 `null` 删除那一项，不存在的 `#id` 追加一项（带上这个 `id`）。按位置和整表替换的写法照旧。`mergeValue`、`layOn`、`composed` 和流式解析都认这种写法。
- 校验只看这次写到的部件，旧作品里不合 schema 的数据不因为别的修改被拒。删除被引用的条目时，引用字段在被引用列表的 `cascade` 里，就删掉引用它的条目（引用列表里的一个 `ref` 只去掉这一个，少于 `min` 时才删条目）；没有声明 `cascade` 而留下悬空引用，是校验错误。
- 作品格式和对话格式各升一版（`CONTEXT_FORMAT`），不写旧数据的升级代码，也不改写 `data/` 里的作品：打开旧作品照样能画，改它时按新 schema 校验。

**可编辑画法协议（EDP）。** 画法在 `DrawingAPI` 上声明画面和数据的对应：`api.text(path)` 这段字就是这个数据路径（编号、单位画在另一个元素里）；`api.part(path, {reorder})` 这组图形是一个列表条目；`api.slot(list, index, {x,y})` 这里可以插入新条目；`api.anchor(list, id, {shape})` 条目可被连接的区域；`api.handle(path, {kind, at, axis, scale})` 拖动改引用、数值或地点；`api.create({list, between, fields, rows})` 从一个锚点拖到另一个时新建条目；`api.outline(d)` 模块可被连接的轮廓。`text`、`part`、`anchor` 给了元素就标在元素上，没给就返回一段属性字符串（`data-edp-*`），拼 SVG 字符串的画法直接写进标签里；其余几个只登记坐标，返回空字符串，所以也能写在模板里。路径用点分，列表条目写 `#id`（`messages.#m3.label`），纯值列表写位置。

`SceneRenderer` 每画完一个模块就核对这些路径在数据（连同默认值）里存在，不存在的经 `options.error` 报出，作者在截图结果里看到。几何在第一次被问到时才量（画布按下、悬停、改字时），按影子 DOM 里元素相对模块外框的位置换算成场景坐标，缓存到模块重画为止，所以作者运行时不为此多做排版。得到的 `EditMap` 是画布和前端唯一依赖的东西：选中部件、按路径改字、插入位、拖动重排、拖手柄、新建条目都只看它，不按图种写特例；任何画法只要声明了，就自动得到同样的编辑能力。截图服务渲染时还数出“画出来但没有标注的数据文字”，`view_canvas` 把它们告诉作者。

**连线端点。** 一端有五种写法：模块 ID（朝向另一端的边，随模块换边）；`{moduleId, at}`，`at` 为边、比例点 `[x,y]`，或 `{along: t}`（沿该模块声明的轮廓，没有声明就沿外框，从左上角顺时针，`t` 是 0..1 的长度比例）；`{linkId, along}`，沿另一条连线两端之间的线段；自由端点 `{x,y}`。

- 沿连线绑定是方案里没有的第五种。理由：从方框底边拉出的线是一条起点绑在方框上、终点自由的连线，在两条这样的生命线之间画的消息要停在所画高度并随参与者移动，只能挂在连线上。备选是把生命线画成和方框编组的手绘线模块（不改协议，但方框缩放时线不跟着居中，而且“从模块拉到空白处”就有了两种结果），或者用超出 0..1 的比例点让连线两端都挂在同一个方框上（语义别扭）。推荐并采用沿连线绑定。
- 拖动模块时，一端挂在它上面、另一端自由的连线，自由端点跟着平移（`moveParts`），所以从方框拉出的线整条跟着走。
- 删除模块或连线时，挂在上面的端点留在原处变成自由端点（服务端没有轮廓，沿轮廓的端点按外框换算，可能挪一点）；两端都自由的是“悬空连线”，选区菜单里可以一起删掉。原来是连线随模块一起删，作者的 `remove.modules` 说明随之改写。
- 连线工具和箭头工具合成一个工具 A（L 也是它）：按下或落下处离模块轮廓近就精确绑定到最近的轮廓点，在模块内部是自动跟随，落在线上沿线绑定，空白处是自由端点；两端都自由时仍是手绘线模块。竖着或横着画的线默认不带箭头头，工具条一键加上。

**撤销与重做在本地。** 会话每提交一次手动修改，就记下这次的 `WorkEdit` 和由前后作品算出的反向修改（`editing` 的 `inverse`），连同选区；⌘Z 提交反向修改，⇧⌘Z 和 ⌘Y 重新提交正向修改。一次手势是一步；连续打字、拖滑块、连按方向键作用于同一部件同一字段且间隔小于 800ms 的合成一步（`composed`）。版本级的回退、放弃修改和“回到此版”不变；服务端 `/undo` 只在本地没有历史时用（刚打开作品）。

## 模块职责

`modules/` 下各模块之间用相对路径（`../x/index.ts`）互相引用。

- `contracts`：作品协议（`Work`、`Scene`、`Instance`、`Link`、`Drawing`、`Brief`、`WorkEdit`）、运行记录（`Run`、`Step`、`ToolActivity`）和设置。前后端、运行时和作者工具共用这一份 schema，它是协议的唯一来源。
- `workspace`：`createWork`、`writeWork`、`setBrief`、`restore`、`undo`，以及 `validateWork`。
- `editing`：把手动操作变成 `WorkEdit` 的纯函数、面板控件的推断（`fieldsOf`/`restOf`，多选共有的 `sharedFields`、条上的 `quickFields`）、拖动与缩放的几何（`snap` 含等距、`resized`、`scaled`）、剪贴板（`copy`/`paste`），以及两个版本之间的差别（`changesBetween`）。前后端和画布都用，不依赖存储和素材库。
- `interchange`：和其他工具交换作品，以及手绘的线。导入都变成一份 `Clip`（`ClipMaker` 逐件拼起），像从别的作品复制来的部件一样粘贴：一次手动编辑、同一套校验，协议、提示词、作者工具和素材库都不知道它。库里没有合适画法的东西用四个作品自带画法承载（`drawings.ts`）：`sketch-line`（手绘线：`points` 是外框内的比例坐标，`smooth` 时按 Catmull-Rom 画成曲线，否则是折线，可带箭头）、`sketch-shape`（Excalidraw 式的矩形、椭圆、菱形：描边与填充分开，斜线、交叉线或实色填充，`roughness` 按 `seed` 固定地抖动线条）、`mermaid`（`api.mermaid` 画 `source`，铺满外框）和 `imported-picture`（导入的图片：整个文件铺满外框，留白和硬边照原样，不像库里的图片画法那样按可见内容缩放、给实景图羽化边缘）；前三种源码第一行是 `// drawy:<种类>` 标记，`kindOfSource` 认它，所以作品给画法换了 ID 导出时仍认得，导入的图片导出时和其他画法一样拍成图片。`inked` 把画笔或箭头的点（画笔先用 `simplify` 去掉半个屏幕像素内的冗余点）变成一个手绘线部件。这些画法的名字会显示在编辑器里，会话的 `ink` 和 `bring` 把剪贴内容放进作品前，按界面语言给它们取名（`i18n.tsx` 的 `edit.made`）。`excalidraw.ts`：`readExcalidraw` 认文件和剪贴板格式；`fromExcalidraw` 先只认颜色写法的颜色（其余换成默认色，两种手绘画法也只把颜色写进标记），按原图的叠放顺序把形状连同框里的字变成 `sketch-shape`，两端都绑在导入部件上的箭头变成库里 `link` 绑定画法的连线（只有起点有箭头时调转方向，点也随之倒过来；全是直角拐弯的箭头记成 `corner` 或 `elbow` 路线，连同先走的方向和横段位置；中间点换算成 `bend`，标签进 - `observation`：截图服务的客户端。`capture.ts` 在截图容器里运行，运行时测试也直接调用它。
- `images`：按作品风格生成图片，并把结果回报给作者。风格参考图由 `styleReferences` 选出，记在素材的 `origin.styleReferences`；生成图一律是该用户的私人素材。抠图角色（object、figure、icon）显影时带 `transparent`，素材库量出没有透明区域就返回 422、不保存，`develop` 用同一提示词再画一次（两次返回图片的张数和 token 都计入，重试失败也保留第一次的用量）；第二次仍不透明就照存，结果带 `opaque`，作者在 `Pictures:` 消息里被告知它会显示成方框。

- `canvas`：前端画布，负责视角、选择（含多选）、移动、缩放、编辑模式和起稿动画（`ink.ts`）。自动视角（`fit`）按 `framing` 摆：`fill` 选项允许时铺满屏幕（短边放下、长边从左上开始越出屏幕），`fit(…, "whole")` 之后一直放下整幅；`showsWhole()` 说视图里是否放得下整幅图（除去 `insets`）。`insets` 最多占画布高度的一半（`clear`）：横拿手机时底部的回复和输入框可能比剩下的地方还高，图就从它们下面透出来，而不是缩成一个点；`SceneView` 盯着 `[data-dock]` 的高度，回复收起、输入框变高时调 `refit()` 让自动视角跟上。`wordsIn(id, at?)` 取用户指的那段字：默认是画布上次被按下的位置（也就是选中模块的地方）下面或指尖范围内的字，没有就取最显眼的（字大、字多），不再取画出的第一段（常常是序号）。`geometry.ts` 的 `fit` 在小屏幕上边距最多 64px、按比例收小，不再固定留 64px。第一次挂载（打开作品、进入子场景）不播放落笔动画，只有之后 `update` 换上的新版本才落笔。不在编辑时，带跳转目标的模块右上角叠一枚小标记（`paintTargets`，放在画布自己的覆盖层里、样式在前端的 CSS 里；运行时页面用同一个 `Canvas`，所以 `browser.ts` 传 `marks: false` 关掉它，截图服务和导出都看不到它），鼠标在模块上时（`hot`）展开写明去处，点它也能打开。`drawn(ids, revision)` 等指定模块画出来，或者确定画不出来（见“前端的分层”），会话靠它选中新做出的模块。手指的手势（双指缩放平移、单指拖动、长按、双击）见“手动编辑如何流动”。画布尺寸变化（面板展开、窗口缩放）时保持画面中心，自动视角在停下 200ms 后平滑适应一次；`fit` 在目标与当前视角几乎相同时不动，避免小幅滑动。Chromium 排 SVG 文字时把屏幕上的缩放算进字体；图层正在做不透明度、滤镜这类动画时它被合成，视角的 `transform` 交给合成器直接改，文字不再重排，于是按旧的缩放画出（大一倍、被裁到布局框里），直到命中测试或重画才恢复。所以运行时给画法的 SVG（`scene.ts` 影子样式里的 `svg`）和画布自己的草图标签都设 `text-rendering: geometricPrecision`，让字体不随屏幕缩放；打开场景时也先定视角再淡入。不要去掉它们。
- `storage`、`identity`：按用户隔离的 `data/drawy.sqlite`，以及账号、角色权限和全站模型配置。`UserStore.viewer`（`{ id, all }`，`all` 来自 `materials.all`）是访问素材库读接口时代表用户的身份，读素材一律传它；写入（预留、显影、上传、记录使用）仍传 `userId`。
- `trace`：基于 AsyncLocalStorage 嵌套记录，任何模块都可以直接调用 `tracer`，不需要层层传参。每个 span 另存一份 `brief`（时间、状态、用量、计量键和几个字的摘要，`spans` 表的 `brief` 列，旧记录在第一次读取时补上）：列表、汇总和时间线（`/api/traces/:id`）只读它，展开某一步时才由 `whole` 经 `/api/traces/:id/spans/:span` 取完整记录，模型轮次连同服务端拼好的完整输入。不要让列表或时间线重新读取完整 span，那会把整段对话读出来。

`materials/` 是独立的素材服务，有自己的 SQLite、文件和检索；`content/` 是策展素材的内容项目（将来独立成闭源仓库），只负责产出素材包，应用和素材服务都不读它的目录。

**素材包是唯一的交付协议**（`materials/pack.ts`，格式 `drawy-material-pack/1`）：`manifest.json`（素材源 `source`、版本 `release`、每个文件的 sha256、类型字典 `types`、编辑能力绑定 `bindings`、数据 `data`、同义词 `synonyms`、明确撤下的 `withdraw`、许可证），加 `materials.ndjson`（每行一个素材，所有类型同一种记录）和它引用的文件。`pnpm --dir content build [输出目录] [版本]` 构建，`pnpm --dir materials library import <目录>` 导入，`library releases`/`rollback <源> <版本>`/`withdraw <id>` 管理。导入先完整校验（文件哈希、schema、ID 重复、类型与载荷是否相符、风格和效果引用、绑定画法是否满足 `capabilityContract`、不能覆盖别的素材源或用户的素材），再把文件按内容哈希存进 `blobs/`，最后一个事务里让新版本可见；同一版本重复导入无副作用，同一版本号换了内容会被拒绝（`materials.ndjson` 也按清单里的哈希校验，所以版本号代表内容；不指定版本时构建脚本用日期加内容摘要命名，内容不同的两次构建不会撞号）；内容变了的素材取所有历史版本之上的新版本号，内容与某个旧版本相同则沿用那个版本号，已给出的版本永远指同一份内容；包里缺少的旧素材不会被删除，撤下要写进 `withdraw`（撤下的素材搜不到，但已持有它的作品仍能按版本读；内容项目的撤下清单是 `content/seed/withdrawn.json`，每个包都带着它，从没持有过这些 id 的库导入时跳过它们）；每次导入记下该源全部素材的版本，`rollback` 回到那时的版本。素材服务启动时只打开数据库，不读任何素材包，也不把素材读进内存。主程序的 `Storage` 打开时也把已存作品和修订里图片的 `role` 改名为 `type`（`system` 表的 `work-format` 记到 2，只做一次），`CONTEXT_FORMAT` 升到 3，旧对话不再续用。打开素材包之前的旧库（`materials(id, data)` 一张表）时，`Catalog` 先把旧表改名，建好新表后只把用户上传和生成的图片（连同归属、状态和使用次数）搬过来，策展素材等素材包导入时再回来。

**类型平级，载荷分开。** 每个素材有一个平级的业务类型 `type`（`object`、`figure`、`scene`、`icon`、`texture`、`drawing`、`effect`、`style`，以及素材包新加的），和一个执行它的载荷格式 `kind`（`picture`、`drawing`、`effect`、`style`，应用只认识这四种）。类型字典来自素材包（`/types`）。新增使用已有载荷的类型不需要改应用。每个素材还有 `version`（见上）。素材包里的图片在作品里的地址带版本（`/materials/files/<id>?v=<版本>`），文件、缩略图和导出都按这个版本取，所以后来的素材包换了同一 id 的图片，已有作品的像素和内容框也不会对不上。另有 `hash`（内容摘要）和 `pack`（来自哪个素材源，用户的为 `null`）。

**存储与检索**（`materials/catalog.ts`）：`materials` 表存每个素材的当前头部（不含画法代码、示例和风格长说明，它们在 `versions` 表的 body 里，读完整素材时才取），`versions` 存每个版本；`search` 是 FTS5 倒排索引（列权重 名称 10、别名 7、标签和分类 3、描述 1，中文按两字一组切词，名称和别名另按单字索引），`names` 是名称的精确索引，`df` 是词频，`thesaurus` 是素材源维护的同义词。一次检索：先从请求里取出背景、视角、朝向这类条件（`search.ts` 的 `facets`，不当关键词搜），在可见范围内（权限、状态、类型在 SQL 里先过滤，再截断）由名称索引和全文索引各取最多 `SEARCH_LIMITS.candidates`（256）个候选，再按覆盖度、命中字段、同义词和条件重排。`match`：名称完全相同是 `exact`；别名相同、同义词与名称相同、或请求的每个词都在它自己的名称别名里是 `close`；只命中部分，或不满足请求的条件，是 `related`。库里没有的词照样计入覆盖度（“青苹果”找到红苹果只能是 `related`），并在结果的 `unknown` 里告诉作者。`browse` 用数据库分页（自己的素材在前，各段按 `created` 走覆盖索引），任何一页的代价都一样；没有任何返回全库的接口，风格的样张最多 4 张、计数用索引统计。`materials/eval/` 有固定的检索评估集（`queries.json` 开发集、`heldout.json` 留出集，`search.ts` 计算 recall@5、MRR、误判和延迟）和规模压测（`scale.ts`），`bench/` 是真实模型的前后对照实测，结果见 [素材库重构对照](materials-refactor/report.md)。

素材严格分公共（`owner: null`：素材包里的素材和被发布的图片）和私人（`owner` 是用户 ID：上传和生成的图片一律如此）。素材服务按请求头识别身份：`x-drawy-user` 是用户，`x-drawy-access: all` 表示可看所有人的素材（由主程序按 `materials.all` 加，客户端用 `viewerHeaders`/`Viewer` 生成）。`browse` 的 `shelf`（`public`/`mine`/`others`，最后一种要求 `all`）把素材分栏；`publish` 把用户的图片设为公共或还给 `origin.user`，素材包里的素材不能改；风格的样张和计数只取公共图片。作者的 `find_materials` 只传用户 ID，不带 `all`。缩略图（`/thumbs/:id?size=`）是白底的 WebP，按内容哈希和尺寸缓存。所有素材共用一个 ID 空间。

**编辑能力绑定。** 应用自己的编辑（加文字、放图片、画连线，以及作者写的连线不指定画法时）用哪个画法，由素材包的 `bindings`（`text`、`picture`、`link`）决定，应用只认识这三种能力；主程序经 `/api/materials/bindings` 交给前端（`apps/web/src/bindings.ts` 的 `loadBindings`，失败后下次再取，编辑操作先等它），`modules/editing/bindings.ts` 的 `setBindings`/`bound` 保存，测试在 `modules/editing/testing.ts` 里设置。

策展内容（`content/seed`）的规则：画法源码在 `drawings/<id>.js`，元数据和示例数据在 `drawings.json`，图片在 `files`，类型字典 `types.json`，同义词 `synonyms.json`（不按评估集调）。结构图与图表画法只用风格 token 上色、可选 `effect` 参数套质感（所以数据里别用 `effect` 当别的字段名）；新加的参数名要在 `i18n.tsx` 的 `edit.params`、选项值在 `edit.options` 补上中英文；画法读取的每个 `d.xxx` 都要在 `params` 里声明（`materials.test.ts` 检查这两条）；`runtime.test.ts` 会用示例数据、以大字号把每个库画法都画一遍。

`detail-<列>-<行>`（1:1000 万陆地、湖泊和岸线，按 15° 分块、精确到千分之一度，缩放级别 ≥ 4.5 时画法只读视图覆盖的几块；块内填色在块边被切开，所以不描边，岸线单独成线）。坐标存成差分整数，单位是 1/scale 度（默认百分之一度，分块文件自带 `scale`）。由 `pnpm --dir content geo` 从 Natural Earth 重新生成（`content/geo.ts`，用 npx 跑 mapshaper，不是依赖）。政治图层只有一个视角（`view`，目前是 Natural Earth 的中国视角）：地图单元、每条边界在该视角下的分类（`FCLASS_<视角>`，不承认的线丢弃）、海上界线、一级行政区归属都按它来。规则对所有国家相同，画法和构建脚本里都不写任何具体国家：行政区裁到它所属单元在该视角下的领土；主权属于别国的单元整体算一个行政区；视角下不存在的单元并入包含它的单元。国名取 CLDR 简称（`Intl.DisplayNames`）。由素材服务的 `/geo/:layer`（读素材包导入的 `data`）提供、主程序经 `/materials/geo/` 转发，画法运行时按需 fetch 并缓存在页面里（读取以任何方式失败都会从缓存里删掉，下次绘制会重试），所以不进作品的素材快照；`runtime.test.ts` 的测试服务器也要提供这条路由。作品快照的是画法代码（固定在取入时的版本），地理数据却是在线读取的，旧作品一直跑旧代码，所以改地理数据的文件格式或图层名时，要让旧版画法仍能读到它期待的东西，或者换一个新的图层名。作者提示词要求不按位置挑库画法输出里的元素来改（库更新后顺序会变），所以作者需要的能力要做成参数，例如按名称突出河流的 `highlights`、边界颜色 `borderColor`。地势晕渲在 `content/seed/geo/relief`：由 `pnpm --dir content relief`（`content/relief.ts`，可用 `NE_RASTERS` 指向已解压的 SR_50M/SR_HR 免得重新下载）从 Natural Earth 的晕渲栅格切成三级经纬度方块（每度 6/30/60 像素，块大小 180°/30°/15°，只留有起伏的块），索引是 `relief.json`（`flat` 是平地和海面的灰度 206），图块经 `/geo/relief/<级>-<列>-<行>` 以 WebP 提供。画法按视图每度像素数选级，把图块画进一张经纬度画布，再对地图的每个像素逆投影取样，比平地暗的画成墨色阴影、亮的画成纸色高光，所以任何投影都适用；缩放级别 7 起渐隐、到 10 消失，在 OpenStreetMap 底图下铺在陆地上、公园水面道路之下，参数 `relief` 可关。投影有两种：经度跨度不到 150° 用按中纬度余弦压缩的等距圆柱，否则用以视图中央经线为中心的 Natural Earth 投影，这时数据线和多边形按中央经线 ±180° 裁开并加密（`pieces`），海面画成地球轮廓加 30° 经纬网，没有比例尺和外框；画法里取坐标一律经 `px`/`unproject`，不要再按线性换算。线条分层：国界是浅色宽带上一条细实线（争议界虚线），省界只画在“主题国家”境内，河流用水色，海岸向海一侧有晕染，线宽在世界和大洲尺度按缩放级别变细。主题国家（`focus`）是地点、路线、区域所在的国家，没有时取视图中心所在国家：只标它们的一级行政区名，其余国家只标国名；国名字号随国家在图上的大小变化，同名只标一次，数据里没有外形框的小单元（礁、小岛）不标。Natural Earth 最细只有 1:1000 万，城市里什么都没有，所以缩放级别 ≥ 7（视图两百公里左右以内）时底图改用 OpenStreetMap 矢量瓦片（OpenMapTiles 结构，默认取 OpenFreeMap 的免 Key 服务，`DRAWY_TILES_URL` 可换成别的 TileJSON 或 `{z}/{x}/{y}` 模板）：素材服务的 `/geo/streets/:z/:x/:y`（`materials/streets.ts`）取瓦片、只留水面、绿地（林地草地和城市公园，不含整片的国家公园和保护区）、水道、按等级分的道路、铁路和水道与主干道名称（只取 OSM 的 `name`，即当地写法，不分语言；要换成读者的语言由作者看图后填 `names` 参数 `{原名: 显示名}`，它替换地图从数据里取来的所有名字，国名、省名、河名、路名都算，`highlights` 用原名或显示名都能找到河），存成以瓦片单位差分编码的 JSON，缓存在素材数据目录的 `streets/<数据源哈希>/` 下（按 `DRAWY_TILES_URL` 分目录，换了数据源不会混用两家的瓦片；文件名带格式版本 `FORMAT`，改了取舍规则就加一，旧缓存自然失效），每块只取一次；所以素材服务需要外网（compose 里与主程序共用 `DRAWY_OUTBOUND_PROXY`）。画法按视图取 `min(14, floor(zoom))` 级的瓦片（最多 36 块），每块裁在自己的方格里画，块边被切开的形状就不会露出来；道路按等级随缩放出现（高速 7、国道 7.5、省道 9、县道 11、更小 12～13.5），铁路从 9 起；这一层下不再画 Natural Earth 的陆地、湖泊和河流，国界省界仍用 Natural Earth 的（政治视角统一），`highlights` 也会按名称找瓦片里的水道。有任何一块读取失败时整张图退回 Natural Earth 并在图上写明街道底图读取失败；画了街道就在角上署名 © OpenStreetMap（ODbL 的要求）。参数 `roads` 关掉道路和铁路（历史地图用，OSM 的海岸、水面和林地照旧，不会退回 Natural Earth 的粗海岸），`roadNames` 关掉路名。`materials/fixtures` 里有一块广州市中心的真实瓦片，素材和运行时测试都用它，不连外网。自动取景在多个地点时最小只留 0.02°，一个城市里的路线不会被放大成整个地区。画法里的通用规则：河流按 Natural Earth 的 `min_zoom` 随比例出现；区域名只在放得进区域时标出，标注点不在视图内或被占时在区域可见部分里找空位；某国的行政区名已标出就不再标国名；路线和区域按“每段走短的一侧”展开，数据线在与视图相交的每份世界副本上都画，跨 180° 经线不断开。`apps/web` 是 React 19 前端，用 CSS Modules 写样式，图标用 lucide-react；`apps/web/src/ui/` 放共用的基础部件（按钮、开关、对话框、提示、菜单定位）、`base.css` 的 token 和字体，`ui/brand/` 是品牌标记与登录页的插画。

## 改动时需要知道的约束

**协议改动要沿整条链同步。** 先改 `contracts`，然后检查这些地方：
- `workspace` 的校验和作者读到的写法 `workspace/author.ts`；
- `editing/apply.ts` 的 `layOn` 和 `composed`；
- 已保存的数据：改了作品的形状，就在 `Storage` 打开数据库时把 `works` 和 `revisions` 在一个事务里升级到新形状（线上是真实用户数据，先备份；现在所有数据都是当前形状，没有留着的升级代码）；同时加 `agent/conversation.ts` 的 `CONTEXT_FORMAT`，旧对话不再续用，只带上用户说过的话和完整作品重新开始；
- `runtime` 的读取；
- `agent/tools.ts` 的工具 schema；
- `agent/prompts.ts` 里对作者的说明；
- `partial.ts` 的流式解析；
- `editing` 的手动编辑和编辑面板；
- 前端的调用方；
- 相关测试。

这样做的原因是，作者只能通过 schema 和提示词知道协议长什么样，任何一处没跟上，模型就会写出无效的作品。画法参数的类型（`contracts` 的 `paramTypes`）也是素材库 `Param` 的可编辑类型，两边一起改。`instanceSchema` 和 `workEditSchema` 的模块里布局字段排在内容字段前面，这是有意的：工具参数按字段顺序流式到达，画布可以先画出构图，再等画法代码。调整字段顺序时要保持这个效果。

**提示词前缀要保持逐字节稳定，且与素材库大小无关。** 同一用户的请求共用一个缓存键。系统提示词描述素材协议，不描述素材库存：不列风格、画法、效果，也不写参数名全集，只写编辑能力绑定的三个画法（`author(bindings)`）。素材库从几百条增长到几十万条，系统提示词逐字节不变（`agent.test.ts` 检查），取材的上下文由 `find_materials` 和 `read_materials` 的上限决定。错误信息也不列出全部风格或画法。

**修改作者提示词和工具说明时，遵循 `prompts.ts` 文件头引用的 Opus 5.5 与 GPT-6 Astra 官方指南。** 用英文写，平实直接，每条要求附上原因，不用大写或 MUST 之类的强调，规则要写具体，不写泛泛的告诫。作者的行为契约也写在这些提示词里：
- 主题说不清时用 `ask_user` 一次问清；
- 简报的依据要逐字引用用户说过的话（`setBrief` 会校验）；
- 简报里的立意（`concept`）是作者自己定的视觉想法，不引用用户的话；第一份简报之前作者先调用 `propose_ideas`（`tools.ts` 的 `proposeSchema`）提出正好三种画法，每种标明种类（`contracts` 的 `ideaKinds`）且种类互不相同，只记在运行步骤（`propose_ideas` 的 `ToolActivity`：`ideas`、`by`、`chosen`、`scores`）里不进作品；`set_brief` 直接收 `briefSchema`，作品还没有简报时要求本次运行已有完成的 `propose_ideas`，且两者不能同轮，否则拒绝保存。例外是用户自己开的作品（`conversation.ts` 的 `userStarted`：没有简报，且在作者第一次保存之前就有模块，即用户从空白手绘或导入后才交给作者；作者开的作品在它第一次写入前总是空的，所以碰不到）：交给作者的整份作品前附一句说明，这些是用户自己的，要保留并在上面接着改，第一份简报直接描述现有画面，不必先提画法，`set_brief` 也就不要求 `propose_ideas`。系统提示词和工具说明不变，这条只在这类作品的消息里出现。`Settings.judge` 存在时，`handlers.ts` 的 `propose_ideas` 交给 `agent/judge.ts` 的 `judgeIdeas`：向 `judge.endpoint`（Gemini Decisions API，`x-goog-api-key`）发一个 `choice` 问题，`input` 只有 `userMessages` 里这件作品用户发过的内容：每条原话一行（`用户请求：…`），附件经 `materials` 的 `attachments`（作者看到的附件也由它取图，`attached` 在其上加说明）取出，图片紧跟在原话后作为 `image` 块（取 512px 缩略图、`resolution: "low"`，每张约 256 token；传原图从容器发出要 8～12 秒，会超过 10 秒的超时），画法和特效只写名字，风格不给；没有图片时 `input` 就是纯文本，什么都没有（只附了风格）时不调用；trace 里图片同其他图片一样按内容存成文件，`criteria` 是 `i0`…`i2` 到想法的文字，不带种类（种类是作者自己标的，问“最有创意”时标着惯例的那种会只因名字被压低），也不带简报（简报的意图是作者围绕自己中意的想法写的，带上会把评选拉回作者的选择）；返回的 `choice` 成为 `develop` 告诉作者，概率记在步骤的 `scores`，用量按 `spendJudge` 记进 `run.usage.judge`。没有评选、10 秒内没答或答非所问时，步骤记 `by: "author"`，工具结果给作者自己选的规则，这次调用不计费，trace 里留一个 `tool`/`judge` span（`meter: "judge"`，`args` 是发出的 `input` 和问题，`usage.input_tokens` 是返回的 `total_input_tokens`），运行记录的“按项目”表因此单列“评选与核对”，费用分项和所用服务也列出它；同一个 `judge` 还核对看图：`performView` 拿到截图后，`checkLook` 在有 `judge`、作者传了 `claims` 且有截图时调用 `checkClaims`，每条 claim 一个 `noul` 是非题（“画面是否做到了：…”），截图以 `resolution: "medium"` 发出（这次看图因没变而略去的场景，附上本次运行里它最近一张整幅截图，`observe` 返回的 `omitted` 列出它们，所以关于它们的 claim 不会拿别的场景来对）（约 520 token 一张，读得清文字和年份；本地容器发一张 200KB 截图约 1～2 秒），`noul` ≥ 0.5 算做到；结果记在 `view_canvas` 步骤的 `checked`（每条的 `claim`、`score`、`holds`），没做到的几条作为一段文字附在这次看图的内容后面要作者先改，用量同样记进 `run.usage.judge`，trace 里是 `check_claims` span；没有 `judge`、没写 claims、没截到图或调用失败时只有作者自己看。`ask` 是两种调用共用的请求、超时和记录；单价默认取 Google 官方定价页 `gemini-decision-1` 的 0.10 美元每百万输入 token。创作模型在工具循环里几乎不做隐式推理，每一轮都使用用户设置的强度；对于在对话内切换强度的格式（GPT-6+、`perTurnEffort` 的 Claude），`Context.baseEffort` 把顶层请求参数固定在对话首次打开时的强度，`requestRole` 沿用该顶层参数，`agent/conversation.ts` 的 `holdEffort` 在跨运行切档或 `withLessThought` 之后追加 `configuration_update` 换回设置值，从而不破坏提示词缓存前缀（`compact` 重建对话后重置 `baseEffort`）。要它发散、评判，得让它写成显式输出：想法写进参数，看图后的评判写成给用户的一句进度；`view_canvas` 把意图和立意放在截图旁边，全图附上 `figure.viewFilled`；`capture.ts` 执行 `checks`/`actions` 时对 `<input type="range">` 避开当前滑块位置点击轨道，使居中默认值的滑块也能触发变更。看图时按“准确→立意是否读得出→工艺”的顺序评判；
- 简报只定图意、事实和所需素材；画布坐标不在思考里算（第一稿思考约占输出的七成，主要花在排坐标上），大致放在 20 单位的格子上就写，看图后再小改，因为多看一次比事先算好便宜得多；`set_brief` 之后紧接着 `generate_images`，让图片在布局时显影；保存和看图放在同一轮；一次看图发现的问题集中在一次写入里改；只剩观众注意不到的润色就停；
- 素材按读者看到它的收获决定：主体和场景氛围值得生图；给普通读者讲日常事物时，主要部分通常也配三到六张图（正式图同样适用），没有外形的概念、长列表和专业图表不配；这些图在简报的 `cast` 和立意里就定好，不等排版后再塞；
- 全图最想让人记住的那句话写成最醒目的文字，放在它说的部分上；
- 看图先查图里关于时间、方向、比例、因果和数字条件的说法，连同立意靠的空间关系一起写成 `claims`（最多 8 条，有决策模型时由它对着截图核对）；有人会据此行动的专业事实（医疗时限、剂量、法律、金融公式、统计）要定向搜索；
- 结束前必须看过最新版本的所有非空场景，并且截图里没有运行错误（`requireObserved`）。

改提示词前先读一遍现有的 `AUTHOR` 和 `guides.ts`，在原有结构里修改，不要另起一套写法。

**提示词的三层。** 常驻指令只放每个作品都用得上的内容，其余按需读取，这样系统提示词每轮带的 token 少，同时前缀依然逐字节稳定。放在哪一层按“多少作品用得上”决定，新增规则时也照此判断：
- 系统提示词（`prompts.ts` 的 `author(bindings)`）：`# Guides` 由 `guideIndex` 从 `guides` 的 `when` 生成，每个主题一行“什么时候读”；`# Library` 只说怎样找、怎样读卡片，以及绑定的三个画法怎样用（它们因此不必先读卡片）。
- 指南（`guides.ts` 的 `guides`，主题列表是 `contracts` 的 `guideTopics`）：`drawing`、`diagrams`、`maps`、`exploration`、`formats`、`copy`。几乎每个作品都要的内容不做成指南：怎样请求图片写在 `generate_images` 的说明和 `pictureRequestSchema` 的字段里，怎样组合图片写在 `AUTHOR` 的 Materials 一节（原来的 `pictures` 指南已删，`i18n.tsx` 保留它的名字给旧记录显示）。指南不点名任何素材（例如地图指南让作者搜索地图画法），所以素材改名或增减不用改指南。指南不再指向别的指南（官方建议引用只深一层）。新增主题要改 `guideTopics`、`guides` 和 `i18n.tsx` 的 `steps.guideTopics` 中英文。
- 卡片（`materials` 的 `card`，由 `read_materials` 读取）：任何类型素材的用法。一次最多 `CARD_BUDGET` 字符，放不下的列出来让作者再读。

`draw_guide` 和 `read_materials` 是工具循环里的普通步骤，结果追加在对话里，不改系统提示词和工具列表，所以不破坏缓存。`guidesRead` 从 `ctx.input` 算出已读的指南和卡片（卡片以结果里实际出现为准，因预算没给出的不算），重复请求只回一句“已在上文”；压缩替换对话后自然清空，可以重新读。`readGuides` 和 `readCards` 返回纯文本：每个指南在 `## 主题` 下，卡片每张一行 JSON。作者可能不读就动手，所以有两处提醒：`set_brief` 的结果在还没读过指南或卡片、也没在同一批里请求时附 `guides`，`write_work` 的结果列出作品用到但没读过卡片的库画法（`cardsUnread`，豁免绑定的三个画法），每个画法只提醒一次。

一轮有多个工具调用时，`loop` 等这一批的结果全部写入后才追加图片消息，因为 DeepSeek 的 Responses 接口把夹在结果之间的消息当成调用没有结果（400）。

输出被截断时三种适配器都抛 `models/types.ts` 的 `CutOff`，带服务方给的原因、usage 和 `thoughtOnly`（只有思考、还没写出内容）。`turn` 把用量计入 `run.usage.failed` 并记进 trace；`thoughtOnly` 时由 `withLessThought` 按该格式改变强度的方式（对话里的 `configuration_update` 或请求参数）以模型接受的最低档重试一次，再失败就停止。这一轮之后由 `holdEffort` 换回设置的强度。

工具说明写清做什么、什么时候用、返回什么和失败时怎样；字段的含义写在 schema 的 `.describe` 里（JSDoc 模型看不到），不在系统提示词里重复。

**界面像绘图工具，不像聊天机器人。** “AI 味”的界面有两波：第一波是靛紫渐变、居中大标语、三张圆角卡片；第二波是有人要求“去 AI 味”后模型给出的米色底、衬线标题、赤陶色点缀（正是 Claude 的配色）。两种都不要。界面的概念是一张制图桌，颜色都在 `apps/web/src/ui/base.css` 的 token 里，每种颜色只做一件事：
- **桌面** `--desk`：偏冷的浅灰（不带暖色），左侧栏、右侧工具条和纸张之间的缝隙（`--gutter`）都是它。
- **纸** `--paper`：白。内容都在纸上：画布、画室和版本面板、设置和素材库页面各是桌上的一张纸（`--r-sheet` 圆角、`--shadow-sheet`），首页的每件作品也是一张纸。`.app-main` 默认就是一张纸，首页和作品页（`:has(> .home, > .workspace)`）自己摆纸；手机上没有缝隙，页面就是整屏。
- **墨** `--ink`：蓝黑。文字，以及“提交”类的主要按钮（`.primary`、发送、新建空白画布）；开关打开也是墨色。
- **蓝铅笔** `--ai`/`--ai-deep`/`--blue`：选中、焦点、链接、正在进行的标记。画布里的 `ACCENT` 与 `--ai` 是同一个蓝，回归验证按这个颜色数选中框，改它要两边一起改。
- **朱印** `--seal`：完成的东西，也就是版本，以及灯笼标志（`--brand` 等于它）。`Title.tsx` 的 `Seal` 是一枚朱红小方印，里面是版本号，像手盖的章：略歪（`rotate`）、四角圆得不一样、印泥透出几点纸色（噪点 `mask`）；版本面板里各印之间连一条手绘铅笔线，当前版旁是描边的“当前”小章。作品页左上角的标题牌、画室里一次运行的成稿、版本面板的每一行、手机顶栏的版本按钮上都是它；不是当前版本时只描边（`quiet`），页面开着时产生了新版本就“盖”一下（`fresh`，`stamp` 动画）。朱红不用在别处，错误用 `--red-text`。

**图标是手绘的。** 侧栏、账户菜单、作品页工具条、手机顶栏、登录窗口、版本面板和首页用 `ui/brand/icons.tsx` 的图标（`import * as Hand`），和灯笼、`PanelMark` 一个笔调：每条边略弯、笔画越过端点一点、圆圈收口时重叠，有的带一点蓝铅笔（`mark-accent` 描线或 `mark-accent-fill` 淡填）。笔画由网格上的点和种子一次算好（`lines`/`shape`/`curve`/`ring`），每次画出来都一样。新图标照这个写法加在那里，不要在这些位置混用 lucide；头像是 `Avatar`，手绘圆圈里的首字母。

**上图板**：手动编辑是这张桌子上的另一种状态，纸被钉上了图板。方格纸、沿上边和左边的标尺、竖在左缘的工具盘（手里的工具是墨色，和开关打开一样）、选区的尺寸标注（蓝铅笔画的尺寸线，两端是建筑制图的 45° 短斜线，数字用 Sofia Sans）是它的样子；对齐参考线和等距间隙用红铅笔（`--red`，画布里的 `CHECK`），因为那是校对用的颜色。画布上的这些标记都在 `modules/canvas` 里用行内样式画（它也在截图容器里运行，没有应用的样式表），颜色与 `base.css` 的 token 手动保持一致；工具盘、条、菜单、标尺在 `app.module.css` 的“The drawing board”一节。新增编辑部件时沿用这套：量度和选中用蓝，校对用红，工具在手用墨，不加新的颜色。

还没出现的图片和截图用 `--hatch` 铅笔排线（`hatch` 动画）。拉丁字母和数字用随包分发的 Sofia Sans（`apps/web/src/ui/fonts`，OFL；DIN 一脉，是工程制图的字），中文用系统黑体（`--font-cjk`）；中文页面用只含字母和数字的 `Sofia Sans Letters`，引号、破折号和间隔号留给中文字体，英文页面用整套 `Sofia Sans`（`:root:not(:lang(zh))`）。标题和正文是同一套字，靠字重（650～750）和字距区分；`--font-serif` 只留给作品里的内容；中文不用斜体。圆角是裁出来的纸角：控件 6～8px（`--r-control`）、卡片 10px、纸 12px，除了状态圆点和步骤节点不用胶囊形；阴影很轻。不用毛玻璃（`backdrop-filter`）和大面积渐变，页面加载时不做上浮动画，动效只回应用户的操作（悬停时封面抬起、按下缩一点、盖印）。不要加模糊色块、流光、闪烁星星这类“AI 生成中”的样子，图标里也不用 `Sparkles`。手机页同样遵守这些：浮在画布上的按钮和底部面板是白底、轻阴影、小圆角，没有渐变和毛玻璃。画室里用户的请求是左对齐的引文，不是对话气泡。页面上不放解释性的提示段落（版本说明、手势说明、代码说明之类），按钮和标签自己说清；作者的思考、提出的画法（`propose_ideas`）和简报的 `concept` 要显示，绘制过程靠它们才有看头：画室把连续的思考合成一行（`Thoughts`），进度行在两次工具之间显示最新思考的标题（`Studio.tsx` 的 `thinkingOf`）：GPT 的思考摘要无论怎么要求都是英文，与页面语言不同的思考照样显示，只用 `lang` 标出并调浅（`foreign`），因为模型推理的几秒到十几秒里，这是唯一能看的东西；画布还空着时 `SceneView` 的便签先抄请求原话，下面一行与进度行同出 `currentOf`（是思考时标“正在想”，否则是正在做的事或作者最新的进度说明），`set_brief` 之后换成主题、想过的画法、选定的想法、受众和画风；语域（严谨/个性）不显示。收起的输入框条用 `Stages` 显示五格进度（`stageOf`：构思、定内容、备素材、起稿、检查，跳过的阶段算已过），画室关着时再加当前一行和 `Clock` 已用时间。token 和费用只给有 `models.manage` 的账号看（`WorkUsage`、运行的费用按钮），普通用户按提问次数计。模块在界面上的名字用 `shownName`（没有名字和文字时是画法名，不露出 ID），`labelOf` 仍是作者看到的名字。界面文案不必处处说“AI”：作者在做的事直接说“正在画”“等你回答”，生成图片的来源标注“AI 生成”保留。

**面向用户的文字要中英双语。** 前端文案在 `apps/web/src/i18n.tsx`，以 `zh` 为基准，`en` 必须有相同的键；服务端内部说中文，错误在离开服务时由 `modules/contracts/messages.ts` 按请求的语言翻译，所以新增的错误信息要在那里补上英文。写给模型的文字保持原样，不翻译。

**测试要验证真实行为。** `agent.test.ts` 用 `vi.mock` 替换掉 `models` 和 `observation`，按脚本逐轮返回工具调用。前端的作品页行为由 `apps/web/regression/` 的三个套件在真实浏览器里验证，见“前端的分层”。素材相关的测试用 `@drawy/materials/testing` 的 `serveLibrary`，在临时目录里起一个带种子数据的真实素材库，并拦截 fetch。新测试沿用这两种方式，不要另写素材库的 mock。测试失败时，先判断是实现错了还是测试过时了，不要为了让测试通过去改断言或写特例。

**`promo/` 是独立工程。** 它是 60 秒宣传片，有自己的 npm 依赖和 `build.sh`，不属于主程序的构建和测试；只有任务明确涉及时才去动它。

Responses 服务是否接受 `max_tool_calls` 和 `tool_choice: allowed_tools` 记在绘制模型的 `toolLimits`，经 `settingsFor` 进入 `Role.toolLimits`，`responses.ts` 的 `narrow` 只读它，不按地址判断。DeepSeek 等不支持的服务由管理员关掉，请求不发送这两项，独立搜索仍在 DrawY 执行时按预算拒绝超额调用，工具列表保持不变。OpenAI 官方 API（`channel === "api"` 且 `toolLimits` 开启）还会把非空 `instructions` 作为 `input` 首位 `developer` 消息发送（`gpt-6.2+` 顶层 `instructions` 不进缓存前缀），并在 `gpt-6+` 请求附带 `text: { verbosity: "low" }`；`oauth` 与第三方接口仍走顶层 `instructions`。
