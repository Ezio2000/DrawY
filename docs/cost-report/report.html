同样 5 句话的提示词，在保持作品可用的前提下，比较三版代码的费用、耗时和画面。第 1 轮是优化前的基线；第 2 轮加入七项流程优化；第 3 轮再改写入格式、错误恢复和第一稿的工作方式。

一句话结论： 第 3 轮把只算 Opus 的费用降了约三分之一，5 个题材全部完成，画面没有整体退步，胸痛一题的内容和时间轴有退步。

最有效的一项： 让作者不在思考里排坐标。第 2 轮的优化只是把思考从简报挪到了第一稿，总量没变（49.6k → 50.0k）；这一项才真正减少了思考。

读这些数字时要注意： 每个题材每轮只跑一次，单题波动很大，看合计比看单题可靠。第 1 轮是顺序运行，后两轮是并发运行，并发让每题都冷启动一次，对后两轮略不利（见方法与口径）。

三轮改了什么

第 2 轮：七项流程优化

方向 改动 结果
截图 去掉自动网格局部图，默认只给全图，模块信息只报变化的部分，自动量最小字号和被裁文字 截图 42 → 21 张
局部修改 新增按模块、连线和单个数据项修改 工具参数 22.2k → 14.5k
基础画法 补上 15 个未公开参数，修好 plot 文字裁切和竖向箭头标签压线（箭头这项在第 3 轮才生效） 加了测试防止再漏
生图 先预留全部 ID，依赖图等被引用的图完成后再画；提示词按表达价值决定是否生图 图片 22 → 11 张，竞争失败未再出现
缓存 在模型上一轮加一个断点，避开 20 块回看窗口 见下方实测
往返 保存和查看同轮，文字收尾且条件满足时直接结束 补 finish 的多余一轮消失
检查 看图前写下要核对的说法（claims），专业事实定向搜索 胸痛开始查指南，咖啡写明摊销条件

缓存断点的实测：同一段对话一次新增 29 个内容块时，不加断点只读到 6,890 token，要重写 46,755 token；加了断点读到 50,208 token，只写 237 token。

这一轮也暴露了问题：小改变便宜后作者反而改得更多，写入和查看从 12 次涨到 16 次，所以 Opus 费用只降了 13%。

第 3 轮：三项针对性改动

改动 做法 依据
不排坐标 提示词要求作者在思考里不算画布坐标，大致放在 20 单位的格子上就写，看图后再小改 第一稿思考占大头；多看一次图只要 $0.03–0.06，多想 1 万 token 约 $0.25
拍平写入 write_work 改成平铺的 modules、links，嵌套从 6 层减到 4 层；bounds 写成 [x, y, 宽, 高]，默认字段可省略，连线只写模块 ID 时自动选边 少写字段，也减少写错括号的机会
坏 JSON 回传 自己读流，把坏参数作为工具错误回给作者，由它改正后重发 不用重来整轮思考，用量真实，原文留在 trace

无效 JSON

工具参数是模型逐字生成的，走 OpenRouter 也没有语法保证：我们测过 strict，连明确违规的 schema 都被接受，说明它没有生效。

范围 写入次数 写坏 JSON
旧代码 Opus（线上 28 次 + 第 1 轮 12 次） 40 0
第 2 轮 16 1（水獭，当时靠重试接住）
一轮已删除的实验（第 3 轮之前） 未留存 1（胸痛，当时整次运行失败）
第 3 轮 10 0

样本太小，还不能说第 3 轮解决了问题，只能说现在写坏时代价更小。回传这条路也只有单元测试和一次手动构造的实验，真实运行里还没被触发过。第 3 轮 Redis 那次失败尝试是网络断流，由原有的重试接住，白等了 67 秒，花了 $0.092。

还没解决的问题

  • 胸痛时间轴： 第 3 轮“hs-cTn 复测”落在“≤90 分钟”刻度下，“1–2 小时”却压在它后面的结果上方，溶栓也没有标时限。这正是检查该防的问题，作者写的 4 条 claims 没覆盖到。
  • 坏 JSON 回传未经真实触发： 要继续积累数据。写坏时原文现在会留在 trace，可以分析。
  • 断流重试没有优化： Redis 一次就白花 $0.092，只能减少损失，防不住。
  • 第一稿仍是最大单项： 第 3 轮 5 题的第一稿合计 19.4k 输出，占 45%。

方法与口径

  • 部署： 本地 Docker（docker compose up -d --build）。
  • 账号： 每轮一个账号。第 2、3 轮都是新账号，没有私人素材，不会复用前面生成的图。
  • 提示词： 5 句完全相同：郑和下西洋路线图、胸痛接诊流程、咖啡店怎么赚钱、小水獭的河边世界、Redis 超卖事故复盘。不追问，不手动修改。
  • 运行方式： 第 1 轮顺序运行，第 2、3 轮 5 题并发（整轮分别用时 236 秒和 198 秒）。并发时每题都要写一次系统前缀（约 18k token），约 $0.45；第 1 轮是 3 次、每次约 15k，约 $0.22。这项差额对后两轮不利，没有从数字里扣除。
  • 没有计入的实验： 中间还跑过一轮同账号重跑和一轮新账号实验。前者复用了基线的图，费用偏低，不可比；后者的数据已按要求清空，只留下那次 JSON 报错。
  • 费用： token 来自运行记录，按 Opus 5.5 的 OpenRouter 配置价计算：输入 $4/M、缓存读取 $0.2/M、缓存写入 $5/M、输出 $20/M。生图 flare 按文字输入 $5/M、图片输入 $8/M、图片输出 $30/M。
  • 失败尝试： 中断的流拿不到输出量，按已收到的字符数除以 3 估算，不含未显示的思考，所以偏低。第 2 轮水獭和第 3 轮 Redis 的失败费用都是这样算的。
  • 思考和参数的拆分： 接口只报告输出总量。工具参数按“字符数 ÷ 3.3”估算，其余算思考，只能看趋势。
  • 第一稿出现： 运行开始到第一次保存成功的时间。第 3 轮 Redis 含断流的 67 秒。
  • 截图： 作者最后一次查看时的全图，缩放到 1200px 宽。
